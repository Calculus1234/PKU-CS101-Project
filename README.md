# PKU CS101 大作业 · 四个独立项目

> **主项目：暗棋引擎**（算法深度最高）
> **第二项目：斗地主残局解牌器**（性能优化过程最完整，且无需 Unity 即可验证）
> 另外两个：游戏《大限将至》、桌宠框架（DesktopPetFramework），展示工程实现与产品落地。

---

## 一、为什么交四个

课程要求写的是「项目可以规模不大，但应当目标明确、能够运行、结果可验证」。这四个项目是过去两个月里真实做出来的东西，各自解决的问题不同：

- **暗棋引擎**回答的是「在信息不完全的博弈里，怎么让 AI 变强」——课程知识（搜索、剪枝、概率推理）用得最深。
- **解牌器**回答的是「一个 NP 级搜索问题，怎么在 8 秒内算完」——算法优化过程有完整的数据记录。
- **《大限将至》**回答的是「NPC 怎么让玩家觉得可信」——行为树、状态机与 LLM 对话的工程实践。
- **桌宠框架**回答的是「怎么让同一个程序跑不同角色、还能不断加能力」——一套 PetFramework
  驱动三只角色，窗口层 / 工具层 / 表现层全部可替换，新增动作池和外部 MCP 只需实现接口再注册。

**主次是明确的**：前两个是算法项目（对应 60 分的「核心功能」+「课程知识」），后两个是工程与产品项目。

## 六、AI 使用声明

**使用工具**：Claude Code / Cherry Studio Agent（Claude 系列）、Unity MCP（编辑器自动化）。

**参与环节**：需求梳理、算法选型讨论、代码编写与重构、性能调优实验、文档整理。

**本人承担的工作**：

- **规则与需求定义**：四个项目的目标、验收标准、边界条件均由本人确定。
- **关键判断**：暗棋引擎的全部 A/B 实验设计（50 局协议、单批负向即回退）；解牌器的「宁可超时也不给错结论」原则；性能方案的选择与否决。
- **验证**：所有结论都用独立手段交叉验证（第三方小程序、人工推演、多批次重复实验）。
- **代码审查**：阅读并修改 AI 生成的代码，多次发现 AI 给出的性能结论与实测不符并纠正。

**验证方法与结果**：见各子项目 README 的「测试与结果」一节。

**引用与复用**：

- 第三方资源：Unity 引擎、Photon（多人）、A* Pathfinding Project、Shell Fur URP 着色器（暗棋/宠物项目使用，未包含在本仓库）。
- 无第三方算法库依赖，核心算法均为本项目实现。
