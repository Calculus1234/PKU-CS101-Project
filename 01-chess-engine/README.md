# 暗棋变体 AI 引擎（Predator）

> 一个**信息不完全**的棋类 AI：双方棋子都带一个公开的「伪装标签」和一个隐藏的真型。
> AI 看到的只是标签和走法几何，必须自己推断对手每颗子到底是什么。

## 一句话概括

**信念推断**（每个敌子一个 7 维概率向量 + 一个「逻辑可能」掩码）→
**采样搜索**（抽 16 个「对手本态」世界，每个世界做 αβ 搜索）→
**根节点约束**（王安全、重子安全、材料风险、尾部风险）→ 最终走法。

详细推导见 [算法导读](docs/引擎算法导读.md)（约 2500 行，含伪代码与源码片段）。

---

## 项目背景

普通象棋、国际象棋是**完全信息**博弈：双方都能看到所有棋子。
这个变体把每颗子的真型藏起来，只暴露一个「看起来像什么」的标签：

- 一个标着「兵」的子，可能是真兵，也可能是真后；
- 走法合法性由**真型**决定，但显示的是**伪装标签**；
- 没有「将军/被将军」规则，**吃真王直接终局**——所以「王在哪」本身也是概率问题。

这带来两个课程里不会遇到的难点：

1. **对手的棋子身份是隐变量**，需要在搜索中显式建模；
2. **玩家会利用伪装**，故意让「像王」的子受威胁来钓鱼，AI 必须考虑这种策略性欺骗。

## 核心算法

### 1. 信念状态（BeliefState）

对每个敌方棋子维护：

```csharp
Body {
    Position Pos;
    PieceType VisibleType;   // 公开的伪装标签
    int PossibleMask;        // 逻辑上仍可能的真型集合（只由走法几何决定，绝不放宽）
    float[7] Probs;          // 7 维概率分布（王/后/车/象/马/兵）
    float TrapRisk;          // 被当作诱饵的风险
}
```

**两套表示缺一不可**：

- `Probs` 是**计数推断**——按「剩余多少子」分配概率。它会因吃子漂移，甚至把某类型压到 0。
- `PossibleMask` 是**逻辑可能集**——只由走法几何收窄，永不放大。

> 踩过的坑：曾经只信 `Probs`，吃掉一个「像后」的子后计数把「后」清零，
> 真后沿开放线吃王时安全扫描完全看不到它。这就是引入 `PossibleMask` 的原因。

### 2. 采样期望搜索

```
公开信息（走法几何、吃子、剩余数量）
        │
        ▼
BeliefState：每个敌子一个 7 维概率 + 可能集掩码
        │ 采样 16 次
        ▼
16 个「确定的敌方本态」世界
        │ 每个世界分别做 αβ 搜索
        ▼
每个根走法在 16 个世界上的平均分
```

**注意「期望」在哪一层**：采样后，每个世界内部是完全信息博弈，αβ 剪枝可以完整使用；
期望只在根节点对 16 个世界取平均。这比在树里枚举所有本态组合便宜得多。

### 3. 搜索优化

| 技术 | 说明 |
| :--- | :--- |
| 迭代加深 | 每次只接受完整完成的一层 |
| 置换表 | 按整盘 hash，深度 ≥ 2 |
| PVS | 非首手零窗口，失败再全窗口 |
| 静态搜索 | 只延伸吃子，消除地平线效应 |
| Delta 剪枝 | 即使白吃对方最大的子也够不到 alpha，剪掉 |
| 走法排序 | TT 最佳手 > MVV-LVA > 杀手 > 历史表 |
| LMR | 默认关闭（A/B 实测：开 76%，关 92%） |

> LMR 那条反直觉：理论上是「减少搜索」，但在这个评估函数下反而降低了胜率，
> 所以按实验数据关掉。**课程知识要给数据让路。**

### 4. 根节点约束（搜索之外）

搜索给的是平均分，但有些错误不能交给平均值权衡：

| 约束 | 类型 | 规则 |
| :--- | :--- | :--- |
| 王安全红线 | 硬 | 走完后真王进入任何「可能本态」攻击范围 → 直接排除 |
| 重子挂子 | 硬 | 存在不挂后/车的走法时，排除会挂大子的手 |
| 材料风险 | 软 | 按期望损失扣分 |
| 尾部风险 | 软 | 最坏世界比平均低超过 450 分时，超出部分 ×0.4 |

**王安全用的是「概率和」而不是布尔值**：8 条射线的攻击概率累加，再叠加马/兵/贴脸王和二步威胁。
因为丢王是立即终局，5% 的隐藏滑子风险也不能赌。

## 战绩

### 对本人

**胜率低于 30%**——本人在这个变体上比 AI 强，AI 目前还打不过。这是项目继续迭代的动力。

### 对其他同学

**全部获胜。** 虽然同学对这个变体的规则不熟悉是主要因素，
但它说明 AI 至少已经具备「不讲道理也能赢」的下限水平。

### 对内置拟人模型（无头对战，50 局固定协议）

| 对手风格 | 胜率 |
| :--- | :--- |
| Aggressive | 98% |
| Defensive | 72~82%（最大短板） |
| Materialist | 78% |
| Positional | 86% |
| Reckless | 90% |

**验收标准是五种风格全部 ≥98%**，目前只有 Aggressive 达标。
这是明确的待办，也是后续两个月的优化方向。

## 工程方法论

这个项目最值得说的不是某个算法，而是**实验纪律**：

1. **固定 50 局协议**：总预算、并发数、时间参数全部固定，只在变量上做 A/B。
2. **单批负向即回退**：任何改动只要在某一风格上退步，立刻撤销，不做「拆东墙补西墙」。
3. **冒烟不能外推**：单局复跑只能证明「机制生效」，不能预测 50 局的胜率。
4. **IL 比对注意**：新增方法会移动 metadata token，IL diff 的数百处差异是假阳性。

开发记录里保留了 v86 → v120 的完整实验史，包括**所有失败的回退**——
这部分比成功记录更有价值，因为它记录了「为什么某些看起来合理的优化其实有害」。

## 局限

1. **对本人胜率仍低于 30%**——模型的地板还不够高。
2. **Defensive 风格只有 72~82%**，是最大短板。
3. **wall-clock 搜索导致结果不完全可复现**：机器负载会改变搜索深度，进而改变走法。
4. **移动端降配**：深度和时间都压缩，胜率会下降。
