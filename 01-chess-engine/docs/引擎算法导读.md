## 0. 一分钟速览

一局棋里，AI 只做三件事：

1. **猜**——对手每个棋子可能是什么（`BeliefState`，概率分布）。
2. **搜**——在“猜出来的若干个世界”里做带剪枝的极小极大（`ExpectiminimaxAI`）。
3. **挑**——在根节点把搜索结果和王安全/掉子风险/隐匿性等硬约束合起来，选一手（`SearchSession` + `PredatorAI`）。

用一张图表示：

```text
公开信息（走法几何、吃子、剩余数量）
        │
        ▼
BeliefState：每个敌子一个 7 维概率向量 + 一个“可能本态”位掩码
        │ 采样 16 次
        ▼
16 个“确定的敌方本态”世界
        │ 每个世界分别做 αβ 搜索
        ▼
每个根走法在 16 个世界上的平均分
        │ 叠加根节点硬约束/软风险
        ▼
最终走法
```

难点全部来自暗棋特有的三条：

- 敌子的“真型”是隐藏信息，AI 只能从**公开走法几何**和**数量守恒**推断；
- 没有“将军/被将军”规则，吃真王即终局，所以“王在哪”本身也是概率问题；
- 玩家也是理性对手，会利用 AI 的伪装（Predator 正是为此而生的外层）。

**全项目最重要的公平性约束**：AI 的任何判断只能读 `VisibleType`、`PossibleMask`、`Probs` 和棋盘位置，永远不能读敌方 `TrueType`。吃子对双方都不揭示本态。

### 0.1 核心公式速查

| 环节 | 公式/规则 |
|---|---|
| 初始信念 | $P_i(t)=\text{remaining}(t)/N$，$N$ 为敌子数 |
| 走法收窄 | `PossibleMask ← PossibleMask ∩ allowed`（交集为空则取 `allowed`） |
| 软收窄 | 不允许本态乘 `TYPE_EPSILON = 0.02`；诱饵走法里王的因子是 `0.25` |
| 吃子条件化 | $P(t\mid \text{非王})=P(t)/(1-P(\text{王}))$；`_remaining[t] -= share` |
| 根期望 | $\text{score}(m)=\frac{1}{W}\sum_{w=1}^{W}\text{Negamax}(w,m)$，$W=16$ |
| 王危险度 | 8 条射线概率和 + 马/兵/贴脸王概率 + $0.5\times$二步威胁 |
| 根选择 | `avg + 位置/欺诈/防守奖励 − 陷阱 − 2.0×材料暴露 − 尾部保险` |
| 挂后阈值 | 真后被任一敌子“可能本态”攻击的概率和 ≥ **0.10** |
| 挂车阈值 | 真车 ≥ **0.25** |
| 尾部保险 | 最坏世界比平均低超过 **450** 分，超出部分 × **0.4** 扣分 |

## 1. 规则与不变量（先读这节）

实现于 `Assets/Scripts/Logic/GameEngine.cs`、`MoveGenerator.cs`。

| 规则 | 实现位置 |
|---|---|
| 每个子有公开的 `VisibleType`（伪装标签）与隐藏的 `TrueType` | `Core/Piece.cs` |
| 走法合法性只看 `TrueType`；显示只看 `VisibleType` | `MoveGenerator.GeneratePieceMoves` |
| **无将军规则**：走进对方火力是合法的 | `MoveGenerator.GenerateLegalMoves`（`:45`） |
| 吃真王立即终局 | `GameEngine.MakeMove`（`:329`） |
| 三次重复：走出第三次的一方判负 | `GameEngine.RecordPosition`（`:181`） |
| 兵首步可两格 | `MoveGenerator.GeneratePawnMoves`（`:148`） |
| 标准开局每方 16 子：8 兵 + 2 车 2 马 2 象 1 后 1 王 | `GameEngine.PlaceStandardPieces`（`:256`） |

走法生成的核心只有两行：

```csharp
public static List<Move> GenerateLegalMoves(Board board, PieceColor color)
{
    // 本变体没有将军/被将规则：只要走法几何合法即可走，王被真正吃掉才结束对局。
    return GeneratePseudoLegalMoves(board, color);
}
```

因此搜索里不需要“过滤送王手”；“送王”的代价由评估和根节点红线承担。

**公平性不变量（整个项目的红线）**：

1. AI 永远不能读敌方 `TrueType`。所有“它可能是 X”都来自 `BeliefState` 的概率/掩码。
2. 吃子**不揭示本态**：双方都只知道“少了一个子”，被吃的必定不是王（否则游戏结束），只按此条件化概率与剩余数量（`BeliefState.NotifyCapture`）。
3. 伪装标签不作为先验：所有入口都 `SetVisibleLabelTrust(0f)`，初始分布只在剩余数量上均匀。
4. 搜索里检查王安全时，用 `BuildFairCheckBoard`（`AIPlayer.cs:509`）：位置/占子取真实棋盘，敌子只挂“几何可能本态”掩码 `GetSafetyMask`，绝不读取真型。
5. 基准对手（`HumanModelAI`）只按同样公开信息行动，不偷看。

## 3. 数据结构

### 3.1 Piece

```csharp
Piece {
    PieceType TrueType;    // 隐藏真型，决定走法
    PieceType VisibleType; // 公开伪装标签，决定显示
    PieceColor Color;
    bool HasMoved;         // 兵首步/王车易位
    int BeliefTypeMask;    // 只在“公平检查棋盘”里临时挂上，见 4.5
}
```

**为什么用值类型 `Position`/`Move`**：搜索里每秒构造几十万次；避免引用类型分配，`Move` 直接做 `Dictionary` 键（`_sums`、置换表等）。

### 3.2 Board

- `Piece[8,8] _squares`，`GetPiece` 带边界检查。
- `Clone()` 深拷贝 64 格（棋子对象也克隆），代价小但**不要在每个叶子里 Clone**。
- `ExecuteMoveWithUndo/UndoMove`：搜索主循环用这一对，返回 `Undo`（含被吃子、易位信息），避免分配棋盘。
- `Board` 本身不维护“棋子列表”，遍历棋子靠 64 格扫描（评估热路径的一部分）。

### 3.3 BeliefState.Body

每个**敌方棋子**位置对应一个 `Body`：

```csharp
Body {
    Position Pos;
    PieceType VisibleType;
    bool HasMoved;
    int PossibleMask;      // 逻辑上仍可能的真型集合（几何证据，绝不因计数推断而放宽）
    float[7] Probs;        // 各真型概率（索引 = PieceType 枚举值：1 王, 2 后, 3 车, 4 象, 5 马, 6 兵）
    float TrapRisk;        // 被人类当诱饵的风险（Predator/评估用）
}
```

全局还有 `_remaining[7]`：敌方每种真型还剩多少个（可以是小数，因为是“期望剩余”）。它是概率归一与吃子条件化的守恒量。

`PieceType` 的数值不是随便定的：

```csharp
None=0, King=1, Queen=2, Rook=3, Bishop=4, Knight=5, Pawn=6
价值：P=100, N=320, B=330, R=500, Q=900, K=20000
```

`Queen=2..Pawn=6` 连续，所以大量代码直接写 `for (int t = 2; t < 7; t++)` 表示“后/车/象/马/兵”。

## 4. 信念推断（BeliefState）

这是暗棋引擎最核心、也最容易被问到的部分。

### 4.1 初始先验：只看数量，不看标签

`ResetFromBoard`（`BeliefState.cs:107`）：

```csharp
float trust = Math.Max(0f, Math.Min(0.95f, VisibleLabelTrust));
float bodyCount = enemies.Count;
foreach (var (pos, piece) in enemies)
{
    var body = new Body
    {
        Pos = pos, VisibleType = piece.VisibleType, HasMoved = piece.HasMoved,
        PossibleMask = MaskFromRemaining()
    };
    for (int t = 1; t < PT_COUNT; t++)
        body.Probs[t] = _remaining[t] / bodyCount * (1f - trust);

    int visible = (int)piece.VisibleType;
    if (trust > 0f && visible > 0 && visible < PT_COUNT)
        body.Probs[visible] += trust;

    _bodies[pos] = body;
}
EnforceCountConstraint();
```

公平模式下 `VisibleLabelTrust = 0`，于是每个位置：

$$
P_i(t)=\frac{\text{remaining}(t)}{N}
$$

标准开局 $N=16$，所以每个未动敌子：

- 王 1/16 = 6.25%
- 后 1/16 = 6.25%
- 车 2/16 = 12.5%
- 马/象各 2/16 = 12.5%
- 兵 8/16 = 50%

“它 50% 是兵”不是偷看，而是数量先验。

> 注意：`VisibleLabelTrust` 不是零时只是“受控实验”的标签先验；几何走法证据仍能推翻它。游戏与基准一律置 0。

### 4.2 走法几何收窄

`NotifyMove`（`BeliefState.cs:297`）每当对手走一步：

```csharp
var allowed = GetTypesThatCanMove(boardBefore, move.From, move.To);
if (allowed.Count > 0)
{
    int allowedMask = 0;
    foreach (var type in allowed) allowedMask |= 1 << (int)type;
    // 可能集只收紧不放宽：若与历史证据冲突，以本次实际走子为准。
    body.PossibleMask = (body.PossibleMask & allowedMask) != 0
        ? body.PossibleMask & allowedMask
        : allowedMask;

    // 受威胁仍不撤：玩家完全可能是在用真王钓大鱼，不能把“王”这一项直接按噪音压掉。
    ApplyWeights(body, allowed, baitMove ? 0.25f : TYPE_EPSILON);
}
```

`GetTypesThatCanMove` 对 6 种真型逐一做几何合法性判断：

```csharp
foreach (var type in AllTypes)
{
    if (MoveGenerator.IsValidMoveForPieceType(board, from, to, type, _enemyColor))
        types.Add(type);
}
```

概率收窄用的是“乘小因子再归一”，而不是直接置零：

```csharp
private void ApplyWeights(Body body, HashSet<PieceType> allowed, float kingDownFactor)
{
    for (int t = 1; t < PT_COUNT; t++)
    {
        if (allowed.Contains((PieceType)t)) continue;
        float factor = t == (int)PieceType.King ? kingDownFactor : TYPE_EPSILON;
        body.Probs[t] *= factor;
    }
    NormalizeRow(body);
}
```

- `TYPE_EPSILON = 0.02`：几何上不可能的本态保留极小残余，防止“证据冲突时把所有质量清零”。
- `baitMove` 时王的因子是 `0.25` 而不是 0.02：玩家可能故意让“像王”的子受威胁而不撤，用真王钓鱼。

**为什么需要 `PossibleMask` 和 `Probs` 两套东西**：

- `Probs` 是“计数推断”，会因吃子/升变漂移，甚至出现“概率被挤到 0”；
- `PossibleMask` 是“逻辑可能集”，只由走子几何决定，**绝不放宽**。
- 王安全红线使用 `GetSafetyMask`（`BeliefState.cs:213`）读 `PossibleMask`，哪怕概率很低也不放过。历史 bug G1：吃掉一个“像后”的子后，计数把“后”清零，真后沿 e 线吃王时安全扫描却看不到它。

### 4.3 吃子：双方都不揭示本态

`NotifyCapture`（`BeliefState.cs:353`）：

```csharp
if (pos.IsValid && _bodies.TryGetValue(pos, out Body body))
{
    float remainingMass = 0f;
    for (int t = 1; t < PT_COUNT; t++)
    {
        if (t == (int)PieceType.King) continue;
        remainingMass += body.Probs[t];
    }

    if (remainingMass > 0.0001f)
    {
        for (int t = 1; t < PT_COUNT; t++)
        {
            float share = t == (int)PieceType.King ? 0f : body.Probs[t] / remainingMass;
            _remaining[t] = Math.Max(0f, _remaining[t] - share);
        }
    }
    // ... 空质量时的均匀扣减保底
    _bodies.Remove(pos);
}
EnforceCountConstraint();
```

三个要点：

1. 被吃的位置从 `_bodies` 删除；
2. 因为游戏没结束，被吃的**一定不是王**：王概率置 0，其余类型按比例条件化；
3. 从 `_remaining[t]` 扣减“期望数量”（按概率份额），而不是扣 1 个具体类型。

这条是公平性的关键：AI 吃玩家的子，也不能知道吃的是什么；玩家吃 AI 的子同理。AI 视角里只是“我的某个子没了”，它自己的 `BeliefState` 甚至根本不跟踪己方。

### 4.4 数量约束：只缩不放，绝不把排除过的本态灌回来

`EnforceCountConstraint`（`BeliefState.cs:494`）是信念的“守恒修复”：

```csharp
for (int iteration = 0; iteration < 6; iteration++)
{
    for (int t = 1; t < PT_COUNT; t++)
    {
        float sum = 0f;
        foreach (var body in _bodies.Values) sum += Math.Max(0f, body.Probs[t]);

        float remaining = Math.Max(0f, _remaining[t]);
        if (remaining <= 0.0001f)
        {
            foreach (var body in _bodies.Values) body.Probs[t] = 0f;
            continue;
        }

        if (sum > remaining)
        {
            float scale = remaining / sum;
            foreach (var body in _bodies.Values) body.Probs[t] *= scale;
            continue;
        }

        float deficit = remaining - sum;
        if (deficit <= 0.0001f) continue;

        float weightSum = 0f;
        foreach (var body in _bodies.Values)
        {
            if ((body.PossibleMask & (1 << t)) == 0) continue;
            weightSum += 0.01f + Math.Max(0f, body.Probs[t]);
        }
        if (weightSum <= 0.000001f) continue;

        foreach (var body in _bodies.Values)
        {
            if ((body.PossibleMask & (1 << t)) == 0) continue;
            body.Probs[t] += deficit * (0.01f + Math.Max(0f, body.Probs[t])) / weightSum;
        }
    }

    foreach (var body in _bodies.Values) NormalizeRow(body);
}
```

伪代码：

```text
重复 6 轮：
  对每种真型 t：
    总量 sum = 所有 Body 的 P(t) 之和
    剩余 remaining = _remaining[t]
    若 remaining = 0：所有 P(t) 清零
    若 sum > remaining：全盘等比缩小到 remaining
    若 sum < remaining：只给 PossibleMask 允许 t 的 Body 补缺口
  每个 Body 归一化
```

**为什么不直接“补到剩余数量”**：旧实现无条件缩放，会把手里的“后”清零后，又按缺口把“后”灌回所有位置，连几何上已经被排除的 Body 也重新获得后概率。G1 就是这样让真后从安全扫描里消失的。v65 的口径是：**数量只约束总量，不推翻几何证据**。

### 4.4.1 升变与吃子的公开信息口径

两种事件都**不揭示被吃子的本态**，双方口径完全一致：

- **吃子**（`NotifyCapture`）：只公开“少了一个子”。棋局没有因此结束是公开信息，所以被吃的必定不是王；按“非王”条件化该 Body 的概率，并从 `_remaining` 里扣掉它的期望数量。双方谁吃谁都不额外获得真型。
- **升变**（`NotifyPromotion(pos, promotionType)`）：升变类型（=Q/R/B/N）本身是公开信息，棋谱和联机包都会携带。因此升变后的 Body 直接**精确绑定**为该类型（`Probs[promoted]=1`，其余 0，`PossibleMask` 只留这一位），同时 `_remaining[Pawn]-1`、`_remaining[promoted]+1`，再跑计数约束。
  - v92 之前这里给车/马/象/后各记 0.25，真后升变后全盘“后”的期望数量长期偏低，王安全与挂子判定会把真后当成 3% 的路人（G24/G35）。升变类型既然公开，就不该再“装不知道”。

### 4.6 置信度

```csharp
// 每个敌子都有一个高概率本态，且王位也基本锁定
public bool IsConfident(float threshold = 0.7f)
{
    float maxKing = 0f;
    double sumMax = 0.0;
    foreach (var body in _bodies.Values)
    {
        float max = 0f;
        for (int t = 1; t < PT_COUNT; t++)
            if (body.Probs[t] > max) max = body.Probs[t];
        sumMax += max;
        float king = body.Probs[(int)PieceType.King];
        if (king > maxKing) maxKing = king;
    }
    return maxKing >= threshold && sumMax / _bodies.Count >= threshold;
}

// 是否存在某个 Body 的 P_King 足够高（王身份锁定）
public bool IsKingIdentityKnown(float threshold = 0.8f)
{
    foreach (var body in _bodies.Values)
        if (body.Probs[(int)PieceType.King] >= threshold) return true;
    return false;
}
```

用途：

- 残局 `IsConfident()` 为真时，只采样一个最大似然世界，换取更深的搜索；
- `IsKingIdentityKnown()` 为假时，深层搜索会删除“吃采样王”的走法（`RemoveKingCaptures`），避免把“也许是王”当成真绝杀，搜出一堆假 MATE；
- 根节点只有 `P_King ≥ 0.75` 的吃王才按“绝杀”结算（`IsConfidentKingCapture`）。

### 4.7 采样：把概率变成一个具体世界

`SampleBoard`（`BeliefState.cs:568`）：

```csharp
public Board SampleBoard(Random rng, int sampleIndex = -1, int sampleCount = 0,
    Func<Position, PieceType, float> typeBias = null)
{
    var board = new Board();
    var bodies = _bodies.Values.ToList();

    int kingIndex = PickKingBody(bodies, rng, sampleIndex, sampleCount);

    var budget = (float[])_remaining.Clone();
    budget[(int)PieceType.King] = 0f;

    for (int i = 0; i < bodies.Count; i++)
    {
        var body = bodies[i];
        PieceType type;
        if (i == kingIndex)
        {
            type = PieceType.King;
        }
        else
        {
            type = SampleType(body.Pos, body, budget, rng, typeBias);
            budget[(int)type] = Math.Max(0f, budget[(int)type] - 1f);
        }

        var piece = new Piece(type, body.VisibleType, _enemyColor)
        {
            HasMoved = body.HasMoved,
            BeliefTypeMask = BuildTypeMask(body, type)
        };
        board.SetPiece(body.Pos, piece);
    }

    return board;
}
```

伪代码：

```text
输入：概率表 _bodies、剩余数量 _remaining
1. 按 P_King 加权抽一个 Body 当王（唯一王）
   - 用黄金比低差异序列 (i*0.618 + u) % 1 代替等距分层
   - 目的：超时只跑了前 k 个世界时，王的位置仍均匀铺满棋盘
2. budget = _remaining，王的预算置 0
3. 其余 Body 依次：
   - 按 Probs 加权抽类型，但只抽 budget > 0 的类型
   - budget[type] -= 1
4. 生成 Piece(trueType=抽到的, visibleType=公开标签)
   - BeliefTypeMask = 概率达阈值的类型 ∪ 本次抽到的类型
5. 返回这个“具体世界”
```

`PickKingBody` 的黄金比分层：


`SampleMostLikelyBoard`（`:607`）是残局专用：不做随机抽样，每个位置取当前概率最高的类型；越自信的位置越先挑，避免低概率位置抢走最后一个后/车。它仍然是“信念塌缩”，不是读取真实本态。

**为什么是 16 个世界**：这是蒙特卡洛近似期望。实测 8 个世界会把胜率从 ~98% 打到 86.7%，因为暗棋的战术分支对“对手到底是什么”极其敏感；16 是精度与速度的平衡点。信念已经高度确定时（`IsConfident(0.8)`）减半到 8，把省下的时间换成更深一层。

### 4.8 一个手算例子

假设标准开局，对手把 b1 的子走到 c3：

- 哪些真型能从 b1 走到 c3？马（b1→c3）和兵（b1→c3？黑兵向下走，方向不对）——只有马能走这个 L 形。后/车/象/王都走不出这个形状。
- 于是 `PossibleMask = {Knight}`，且 `Probs` 里非马质量乘 0.02 后归一，马概率接近 100%。
- 下一次这个子再从 c3 走直线，若几何上只有车/后能走，`PossibleMask` 与 allowed 的交集为空，代码以本次证据为准把 `PossibleMask` 设为 allowed——这说明前一条证据解释不了这次走法，必须以新证据为准（例如中途升变/易位等规则特例）。

```csharp
private void EvaluateRootMove(Move move, int depth)
{
    if (_merged.GetPiece(move.From) == null) { _skipMissing++; return; }

    // 王安全红线：这一步会让真王进入敌方可能的攻击范围，整手弃用。
    if (_kingRedLine.Contains(move)) { _skipRed++; return; }
    // 大子暴露硬约束：存在“不挂后/挂车”的走法时，不选会挂大子的手。
    if (_hangingHeavy.Contains(move)) { _skipHanging++; return; }

    var undo = _merged.ExecuteMoveWithUndo(move);
    int score;
    bool capturedSampledKing = undo.Captured != null && undo.Captured.TrueType == PieceType.King;
    if (capturedSampledKing)
    {
        score = _owner.SampleKingCaptureScore(move.To);
    }
    else
    {
        if (_owner.IsOwnKingCapturable(_merged)) AddKingLoss(move);

        score = -_owner.Negamax(_merged, depth, -INF, INF,
            OpponentColor(_owner._color), _stopwatch, _tt, 1, _buffers);
    }
    _merged.UndoMove(move, undo);

    // 预算耗尽的走法只有静态估值，不能进根平均。
    if (_owner.SearchAborted) { _skipAborted++; return; }
    AddScore(move, score);
}
```

### 5.3 “期望”到底在哪一层

这是最容易理解错的地方：

- **采样世界在搜索树内部是固定的**。一旦 `BeginSample` 选好了敌方本态，子树就是完全信息、确定性的 αβ 搜索。
- **期望只在根节点做**：同一个根走法在 16 个世界各搜一次，取平均：

```csharp
private void AddScore(Move move, int score)
{
    double sum;
    _sums.TryGetValue(move, out sum);
    _sums[move] = sum + score;

    int count;
    _counts.TryGetValue(move, out count);
    _counts[move] = count + 1;

    int min;
    if (!_minScores.TryGetValue(move, out min) || score < min)
        _minScores[move] = score;
}
```

$$
\text{rootScore}(m)=\frac{1}{16}\sum_{w=1}^{16}\text{Negamax}(w,m)
$$

严格说这不是“在树里做期望节点”，而是**对信念做蒙特卡洛采样，再在每个样本里做确定性搜索**。这样做的原因是：

1. 暗棋的隐藏信息不在“敌方随机走子”，而在“敌方是什么子”；
2. 一旦假定敌方本态，走子就是确定的博弈，αβ 剪枝可以完整使用；
3. 采样 16 次比在树里枚举所有本态组合便宜得多。

### 5.4 迭代加深与“作废层”

- `CompleteDepth`（`:1307`）：若本层中途超时（`SearchAborted`），**整层作废**，沿用上一个完整层的结论，避免“一半走法搜了 6 层、一半只有静态分”的污染（v14 修复）。
- 万一连一层都没完成，`SelectStaticFallback`（`:1515`）用静态评估兜底。
- 深度推进时只清空根统计，不重建采样世界；采样只在会话创建时做一次。

### 5.5 Negamax（`:2452`）

标准负极大值 + 这些工程：

| 技术 | 位置/条件 |
|---|---|
| 置换表（按整盘 hash） | 深度 ≥ 2；TT 存 depth/value/flag/bestMove |
| PVS | 非首手先零窗口，失败再全窗口重搜 |
| LMR | 默认关闭（50 局 A/B：开 76%，关 92%）；开启时零窗口、深度 ≥ 3、安静走法、第 5 个起减 1 层、第 9 个起深节点减 2 层；攻击敌王的走法不减 |
| 王线延伸 | 深度 1~2 时，对手静着走到“能攻击我真王”的位置 → 子深度不降 |
| 吃王终局 | `MATE - ply`，越快吃越优 |
| 走法排序 | TT 最佳手 > 吃子/升变（MVV-LVA）> 杀手 > 历史表 |
| 无子可动 | 直接返回静态评估（本变体没有“无子可动”败北） |

核心代码：

```csharp
private int Negamax(Board board, int depth, int alpha, int beta, PieceColor side,
    Stopwatch stopwatch, Dictionary<ulong, TTEntry> tt, int ply, List<Move>[] buffers)
{
    if (stopwatch.ElapsedMilliseconds > SearchTimeBudgetMs)
    {
        SearchAborted = true;
        return Evaluate(board, side);
    }

    // 置换表
    TTEntry entry = default;
    bool ttHit = false;
    ulong key = 0UL;
    bool useTt = tt != null && depth >= 2;
    if (useTt)
    {
        key = HashBoard(board, side);
        if (tt.TryGetValue(key, out entry))
        {
            ttHit = true;
            if (entry.Depth >= depth)
            {
                if (entry.Flag == 0) return entry.Value;
                if (entry.Flag == 1 && entry.Value >= beta) return entry.Value;
                if (entry.Flag == 2 && entry.Value <= alpha) return entry.Value;
            }
        }
    }

    if (depth <= 0)
        return Quiescence(board, alpha, beta, side, stopwatch, ply, 0, buffers);

    _nodeCount++;
    var moves = buffers[ply];
    MoveGenerator.GeneratePseudoLegalMoves(board, side, moves);

    // 王身份未锁定时禁止 AI 在深层追“采样敌王”
    if (side == _color)
        RemoveKingCaptures(board, moves);
    if (moves.Count == 0)
        return Evaluate(board, side);

    OrderMoves(board, moves, ply, side);
    if (ttHit && entry.HasBestMove)
        PromoteMove(moves, entry.BestMove);

    int alphaOriginal = alpha;
    int best = -INF;
    Move? bestMove = null;
    bool firstMove = true;
    int quietTried = 0;

    // 王线延伸：只在深度 1~2 的濒视界层，给“对手静着逼近真王”的走法补一层
    Position? extendKing = KingLineExtensionEnabled && depth >= 1 && depth <= 2 && side != _color
        ? board.FindKing(_color)
        : (Position?)null;

    foreach (var move in moves)
    {
        if (stopwatch.ElapsedMilliseconds > SearchTimeBudgetMs)
        {
            SearchAborted = true;
            break;
        }

        var undo = board.ExecuteMoveWithUndo(move);
        int childDepth = depth - 1;
        if (extendKing.HasValue && undo.Captured == null)
        {
            var moved = board.GetPiece(move.To);
            if (moved != null && moved.Color == side &&
                MoveGenerator.CanPieceAttackSquare(board, move.To, moved.TrueType, moved.Color, extendKing.Value))
                childDepth = depth;
        }

        // LMR（默认关闭）
        int reduction = 0;
        if (UseLateMoveReduction && beta - alpha == 1 && depth >= 3 &&
            undo.Captured == null && !move.PromotionType.HasValue &&
            childDepth == depth - 1 && quietTried >= 4 && childDepth > 1)
        {
            // ... 攻击敌王格的走法不减
        }

        int score;
        if (undo.Captured != null && undo.Captured.TrueType == PieceType.King)
        {
            score = MATE - ply;
        }
        else if (firstMove)
        {
            score = -Negamax(board, childDepth, -beta, -alpha,
                OpponentColor(side), stopwatch, tt, ply + 1, buffers);
        }
        else
        {
            // PVS：零窗口先确认“这步不可能优于当前最优”，失败才全窗口重搜一次
            int searchDepth = childDepth - reduction;
            score = -Negamax(board, searchDepth, -(alpha + 1), -alpha,
                OpponentColor(side), stopwatch, tt, ply + 1, buffers);
            if (score > alpha && (reduction > 0 || score < beta))
                score = -Negamax(board, childDepth, -beta, -alpha,
                    OpponentColor(side), stopwatch, tt, ply + 1, buffers);
        }
        board.UndoMove(move, undo);
        if (undo.Captured == null && !move.PromotionType.HasValue) quietTried++;
        firstMove = false;

        if (score > best) { best = score; bestMove = move; }
        if (best > alpha) alpha = best;
        if (alpha >= beta)
        {
            RecordCutoff(move, undo.Captured != null, ply, side, depth);
            break;
        }
    }

    if (best == -INF) best = Evaluate(board, side);

    // 存 TT（绝杀分不存，避免 ply 失真）
    if (useTt && stopwatch.ElapsedMilliseconds <= SearchTimeBudgetMs && Math.Abs(best) < MATE - 100)
    {
        byte flag = best <= alphaOriginal ? (byte)2 : (best >= beta ? (byte)1 : (byte)0);
        tt[key] = new TTEntry { Depth = depth, Value = best, Flag = flag,
            BestMove = bestMove ?? default, HasBestMove = bestMove.HasValue };
    }

    return best;
}
```

Negamax 的伪代码：

```text
Negamax(board, depth, alpha, beta, side):
    若超时：标记 aborted，返回静态评估
    若 depth >= 2：查置换表，命中且深度足够则直接返回/剪枝
    若 depth <= 0：返回 Quiescence(...)

    moves = 生成 side 的所有走法
    若 side 是我方且王身份未锁定：删除“吃采样王”的走法
    若没有走法：返回静态评估

    排序：TT 最佳手 > 吃子/升变 > 杀手 > 历史表
    best = -INF
    对每个走法 m：
        执行 m（记录 Undo）
        若吃到王：score = MATE - ply
        否则：
            childDepth = depth - 1
            若 m 是“逼近我真王”的静着且 depth <= 2：childDepth 不降
            首手：全窗口搜索
            其余：零窗口搜索；失败且未剪枝则全窗口重搜（PVS）
        撤销 m
        best = max(best, score)；alpha = max(alpha, best)
        若 alpha >= beta：记录杀手/历史，break
    存置换表（不含绝杀分）
    返回 best
```

负极大值的含义：当前节点返回“从 `side` 视角看的最好分”。子节点取负，所以每一步都在“我最大化、对手最大化他自己的视角 = 最小化我的分”。

### 5.6 静态搜索 Quiescence（`:2621`）

为什么需要它：普通 αβ 在深度 0 直接调用静态评估，会停在“刚吃完子、还没被反吃”的局面，产生地平线效应。静态搜索只延伸吃子/升变，把交换走完。

```csharp
private int Quiescence(Board board, int alpha, int beta, PieceColor side,
    Stopwatch stopwatch, int ply, int qDepth, List<Move>[] buffers)
{
    _qNodeCount++;
    _qDepthSum += qDepth;

    int standPat = Evaluate(board, side);
    if (qDepth >= MaxQuiescenceDepth) return standPat;
    if (stopwatch.ElapsedMilliseconds > SearchTimeBudgetMs)
    {
        SearchAborted = true;
        return standPat;
    }

    if (standPat >= beta) return beta;

    // Delta 剪枝：就算下一手白吃对方最大的子（900）再加 200 也够不到 alpha，整棵子树放弃
    if (standPat + 900 + 200 < alpha) return standPat;
    if (standPat > alpha) alpha = standPat;

    var buffer = buffers[ply + qDepth];
    MoveGenerator.GeneratePseudoLegalMoves(board, side, buffer);

    bool ownKingCaptureAllowed =
        side == _color && _beliefState.IsKingIdentityKnown(KingCertainThreshold);

    // 只保留吃子与升变
    int write = 0;
    for (int i = 0; i < buffer.Count; i++)
    {
        var m = buffer[i];
        var target = board.GetPiece(m.To);
        if (side == _color && !ownKingCaptureAllowed && target != null &&
            target.TrueType == PieceType.King)
            continue;
        if ((target != null && target.Color != side) || m.PromotionType.HasValue)
            buffer[write++] = m;
    }
    if (write < buffer.Count) buffer.RemoveRange(write, buffer.Count - write);
    OrderMoves(board, buffer, ply + qDepth, side);

    foreach (var move in buffer)
    {
        // ... 超时检查
        var target = board.GetPiece(move.To);
        if (target != null && standPat + target.TrueType.GetValue() + 200 < alpha)
            continue;

        var undo = board.ExecuteMoveWithUndo(move);
        int score;
        if (undo.Captured != null && undo.Captured.TrueType == PieceType.King)
            score = MATE - ply;
        else if (side == _color && IsOwnKingCapturablePessimistic(board, out _))
        {
            // 静态搜索也不许“贪一口”：吃完把真王交出去，直接截断为负绝杀。
            score = -MATE + ply;
        }
        else
            score = -Quiescence(board, -beta, -alpha,
                OpponentColor(side), stopwatch, ply, qDepth + 1, buffers);
        board.UndoMove(move, undo);

        if (score > alpha) alpha = score;
        if (alpha >= beta)
        {
            RecordCutoff(move, undo.Captured != null, ply + qDepth, side, 1);
            break;
        }
    }

    return alpha;
}
```

关键安全阀：`IsOwnKingCapturablePessimistic` 用公平检查棋盘（敌子挂安全掩码）判断“我的真王会不会被任何可能本态立即吃”。如果是，整个分支按 `-MATE + ply` 截断。这样即使静态搜索吃到一个大子，只要送王就不算收益。

注意：每个 qnode 都调用完整 `Evaluate`，所以**叶子评估成本 = 搜索速度的瓶颈**（见第 9 节）。

## 6. 根节点：搜索之外的决策层

搜索给出“每个走法在 16 个世界里的平均分”，但暗棋里有些错误不能交给平均值去权衡：

- 丢真王 = 立即终局；
- 丢真后/真车 = 大概率输；
- 低概率的“可能本态”也足以在 50 局里偷走一两局。

所以根节点有**四道约束**，两硬两软：

```text
1. 王安全红线 _kingRedLine      （硬：直接跳过该走法）
2. 重子挂子   _hangingHeavy      （硬：直接跳过该走法）
3. 材料风险   _materialRisk      （软：从选择分里扣）
4. 尾部风险   _minScores         （软：从选择分里扣）
```

执行顺序是 `ComputeKingSafety()` → `ComputeMaterialRisk()`，因为挂子过滤需要知道红线集合，才能处理“两套硬过滤联手封死全部走法”的情况。

### 6.1 王安全红线：概率，而不是布尔值

旧实现按“掩码里有没有攻击型”一刀切，问题有两个：

- 低概率的滑子（3% 的后）会被漏掉，但真王被吃是终局；
- 没有安全手时只挑“危险度最低”的一手，经常变成沿后排挪王送死。

现在用**期望危险度**：

```csharp
internal double KingDangerScore(Board board)
{
    var kingPos = board.FindKing(_color);
    if (!kingPos.HasValue) return double.MaxValue;

    Position king = kingPos.Value;
    PieceColor enemy = OpponentColor(_color);
    double danger = 0.0;

    // 8 条射线：只检查每条射线遇到的第一个子
    for (int d = 0; d < AllDirs.Length; d++)
    {
        int dx = AllDirs[d].X, dy = AllDirs[d].Y;
        bool diagonal = dx != 0 && dy != 0;
        for (int x = king.X + dx, y = king.Y + dy; x >= 0 && x < 8 && y >= 0 && y < 8; x += dx, y += dy)
        {
            var piece = board.GetPiece(x, y);
            if (piece == null) continue;

            var pos = new Position(x, y);
            if (piece.Color == enemy)
                danger += AttackProbability(pos, piece, diagonal);
            break;
        }
    }

    // 马位
    foreach (var offset in KnightOffsets)
    {
        Position pos = king + offset;
        if (!pos.IsValid) continue;
        var piece = board.GetPiece(pos);
        if (piece != null && piece.Color == enemy)
            danger += TypeProbability(pos, piece, PieceType.Knight);
    }

    // 兵（注意方向：从王的角度看敌方兵在斜前方）
    int pawnDir = enemy == PieceColor.White ? 1 : -1;
    for (int dx = -1; dx <= 1; dx += 2)
    {
        var pos = new Position(king.X + dx, king.Y - pawnDir);
        if (!pos.IsValid) continue;
        var piece = board.GetPiece(pos);
        if (piece != null && piece.Color == enemy)
            danger += TypeProbability(pos, piece, PieceType.Pawn);
    }

    // 贴脸敌王
    for (int d = 0; d < AllDirs.Length; d++)
    {
        Position pos = king + AllDirs[d];
        if (!pos.IsValid) continue;
        var piece = board.GetPiece(pos);
        if (piece != null && piece.Color == enemy)
            danger += TypeProbability(pos, piece, PieceType.King);
    }

    return danger;
}

private double AttackProbability(Position pos, Piece piece, bool diagonal)
{
    double prob = TypeProbability(pos, piece, PieceType.Queen);
    return diagonal
        ? prob + TypeProbability(pos, piece, PieceType.Bishop)
        : prob + TypeProbability(pos, piece, PieceType.Rook);
}
```

`TypeProbability` 只在 `BeliefTypeMask` 允许的集合内条件化：

```csharp
private double TypeProbability(Position pos, Piece piece, PieceType type)
{
    // 信念里没有该子时不能当“安全”，按未知本态等概率处理。
    int mask = piece.BeliefTypeMask;
    if (mask == 0) return 1.0 / 6.0;

    // 走子几何已经排除的本态绝不计入威胁；其余在可能集内条件化。
    if ((mask & (1 << (int)type)) == 0) return 0.0;

    double inSet = 0.0;
    for (int t = 1; t < 7; t++)
    {
        if ((mask & (1 << t)) == 0) continue;
        double p = _beliefState.GetProbability(pos, (PieceType)t);
        if (!double.IsNaN(p) && p > 0.0) inSet += p;
    }

    // 计数近似把质量挤到可能集之外时，按集内均匀处理——不能因此把真威胁当不存在。
    if (inSet < 0.02)
    {
        int count = 0;
        for (int t = 1; t < 7; t++)
            if ((mask & (1 << t)) != 0) count++;
        return count > 0 ? 1.0 / count : 0.0;
    }

    double prob = _beliefState.GetProbability(pos, type);
    if (double.IsNaN(prob) || prob < 0.0) return 0.0;
    return prob / inSet;
}
```

再叠加“二步威胁”`ConditionalKingDanger`（`:2239`）：敌子先吃掉我方一个挡子，再从落点攻击王格。中间还隔我们一手（可逃/可反吃），按半权计入：

```csharp
double dangerScore = _owner.KingDangerScore(fair)
    + KingConditionalDangerWeight * _owner.ConditionalKingDanger(fair);
```

`KingConditionalDangerWeight = 0.5`。

`ComputeKingSafety`（`:943`）对每个根走法：

```text
fair = BuildFairCheckBoard(当前棋盘)
dangerNow = KingDangerScore(fair) + 0.5 * ConditionalKingDanger(fair)

对每个根走法 m：
    在 fair 上执行 m（fair 是克隆，敌子只挂安全掩码）
    danger(m) = KingDangerScore(fair') + 0.5 * ConditionalKingDanger(fair')
    若 m 是低置信度吃王手：danger(m) *= (1 - p)
    记录 _kingDanger[m]（立即被吃的威胁数）和 _kingDangerScore[m]（期望危险度）
```

然后按三层策略决定红线：

#### 第一层：存在“任何可能本态都够不到王”的走法（v66 起零容忍）


#### 第二层：没有干净手，但有低危险手

#### 第三层：一手安全手都没有

1. **高置信度吃王手**：`KingKillProbability ≥ 0.8`，这一手基本结束对局；

### 6.2 重子挂子：存在干净手时，不许主动挂后/挂车

`HasHangingHeavyPiece`（`:3516`）只看走完后的真后/真车：

```csharp
foreach (var (pos, piece) in fair.GetPiecesOfColor(_color))
{
    if (piece.TrueType != PieceType.Queen && piece.TrueType != PieceType.Rook) continue;

    double threshold = piece.TrueType == PieceType.Queen
        ? QueenHangingThreshold   // 0.10
```

为什么后和车阈值不同：

- 伪装标签让对手常以“吃便宜子”的心态扑后。v63 三场平局全是车换掉伪装成兵的真后，之后只能靠王吃回子力、以 K vs K 结构性和棋收场。
- 真后被吃的期望损失远大于任何位置收益，所以零容忍（10%）；车可以稍微宽一点（25%）。

`ComputeMaterialRisk`（`:790`）先算软风险，再做两轮冲突处理：

```csharp

foreach (var move in _rootMoves)
{
    double risk = _owner.EstimateOwnMaterialExposure(_board, move);
    if (risk > 0.5) _materialRisk[move] = risk;
    if (_owner.HasHangingHeavyPiece(_board, move))
        _hangingHeavy.Add(move);
    else
        anyClean = true;
}

// 只有存在“不挂大子”的走法时才做硬过滤；全盘都挂子时交回期望搜索。
if (!anyClean)
{
    _hangingHeavy.Clear();
}
else
{
    // 王安全红线与挂子过滤可能联手封死全部根走法（G32），冲突时优先保王
    bool anySearchable = false;
    for (int i = 0; i < _rootMoves.Count; i++)
    {
        var m = _rootMoves[i];
        if (!_kingRedLine.Contains(m) && !_hangingHeavy.Contains(m))
        { anySearchable = true; break; }
    }
    if (!anySearchable)
    {
        _hangingHeavy.Clear();
        Log("[AI] 王红线与挂子过滤封死了全部根走法：优先保王，放开挂子过滤交给期望搜索。");
    }
}
```

两条规则：

1. **任何手都不干净时，清空挂子过滤**。否则全部根走法被跳过，搜索 0 节点退化成静态兜底，反而白送皇后（G32）。
2. **两套硬过滤冲突时优先保王**：丢王立即终局，丢大子只是劣势。

### 6.3 真后强制救援（v65）

旧的“走完后完全不挂”硬过滤有个死角：真后已经被敌马 100% 咬住时，所有走法都“挂后”，于是 `anyClean = false`，过滤被整体清空，引擎依旧挪王送后（G6 冒烟）。

v65 改成比较“走前/走后”的真后危险度：

```csharp
double queenNow = CurrentQueenAttackChance(_board);
if (queenNow >= QueenHangingThreshold)
{
    var ideal = new List<Move>();
    var better = new List<Move>();
    foreach (var move in _rootMoves)
    {
        if (_board.GetPiece(move.From) == null) continue;
        double after = QueenAttackChanceAfter(_board, move);
        if (after < QueenHangingThreshold) ideal.Add(move);
        else if (after < queenNow - QueenEvacImprovement) better.Add(move);
    }

    var rescue = ideal.Count > 0 ? ideal : better;
    bool anyRescueSearchable = false;
    foreach (var m in rescue)
    {
        if (!_kingRedLine.Contains(m)) { anyRescueSearchable = true; break; }
    }

    if (rescue.Count > 0 && rescue.Count < _rootMoves.Count && anyRescueSearchable)
    {
        var rescueSet = new HashSet<Move>(rescue);
        foreach (var move in _rootMoves)
        {
            if (!rescueSet.Contains(move))
                _hangingHeavy.Add(move);
        }
        Log($"[AI] 真后已在火力下（危险度 {queenNow:P0}）：强制救援，保留 {rescue.Count}/{_rootMoves.Count} 手。");
    }
}
```

伪代码：

```text
queenNow = 当前真后被敌方“可能本态”攻击的概率（多攻击者取最大值，封顶 1.0）
若 queenNow >= 0.10：
    ideal  = 走完后 < 0.10 的所有手
    better = 走完后比 queenNow 至少低 0.15 的所有手
    rescue = ideal 非空 ? ideal : better
    若 rescue 非空、不是全部手、且至少一手不在王红线里：
        把所有不在 rescue 里的手加入 _hangingHeavy
```

`CurrentQueenAttackChance` / `QueenAttackChanceAfter` / `MaxQueenAttackChanceOn` 全部基于 `BuildFairCheckBoard`，只读敌方安全掩码与概率。

### 6.4 材料风险（软约束）

`EstimateOwnMaterialExposure`（`:3447`）对每个非王子：

```csharp
bool defended = IsSquareAttackedByAI(fair, pos);
double ownValue = Math.Min(piece.TrueType.GetValue(), 900);
double chance = 0.0;
int cheapest = int.MaxValue;

foreach (var (epos, epiece) in fair.GetPiecesOfColor(enemy))
{
    int mask = epiece.BeliefTypeMask;
    if (mask == 0) continue;

    // 王亲自扑子归王安全红线管，这里只算子力交换
    for (int t = 2; t < 7; t++)
    {
        if ((mask & (1 << t)) == 0) continue;
        var type = (PieceType)t;
        if (!MoveGenerator.CanPieceAttackSquare(fair, epos, type, enemy, pos)) continue;

        float p = _beliefState.GetProbability(epos, type);
        if (p <= 0.001f) continue;

        int value = Math.Min(type.GetValue(), 900);
        if (value < cheapest) cheapest = value;
        // 有保护不等于对手就不吃：人类常用低子硬吃大子，兑掉也赚。
        // 保护只能降低净损失（后续兑回最便宜攻击子），不能降低被抓的概率。
        chance += p * (defended ? 1.0 : 0.9);
    }

    // 敌方王只在无保护时计入
    if (!defended && (mask & (1 << (int)PieceType.King)) != 0 &&
        MoveGenerator.CanPieceAttackSquare(fair, epos, PieceType.King, enemy, pos))
    {
        float pk = _beliefState.GetProbability(epos, PieceType.King);
        if (pk > 0.05f) chance += pk * 0.9;
    }
}

if (chance <= 0.0) continue;
if (cheapest == int.MaxValue) cheapest = 100;

double swing = defended ? ownValue - cheapest : ownValue;
if (swing > 0.0)
    risk += Math.Min(1.0, chance) * swing;
```

即：

$$
\text{期望损失} = \min(1,\ \text{被吃概率和}) \times
\begin{cases}
\text{己方价值} - \text{最便宜攻击子价值}, & \text{有保护}\\
\text{己方价值}, & \text{无保护}
\end{cases}
$$

选择时乘风险厌恶系数：

```csharp

    selection -= exposureRisk * MaterialRiskWeight;  // 2.0
```

### 6.7 绝杀快速通道（在搜索之前）

`FindImmediateKingCapture`（`AIPlayer.cs:185`）在进入任何搜索前先扫一遍合法走法：只要存在一步能吃到 `P_King > 0.2` 的敌子，就直接返回该步（0ms，必定结束对局或大概率结束）。

```csharp
for (int i = 0; i < moves.Count; i++)

    if (target == null || target.Color == _color) continue;

    float pKing = _beliefState.GetProbability(moves[i].To, PieceType.King);

        if (pKing < 0.9f && WouldLoseOwnKing(board, moves[i])) continue;

        if (pKing < 0.9f && WouldHangOwnHeavy(board, moves[i]))
            continue;

        if (pKing < 0.8f)
        {

            if (attacker != null && attacker.TrueType.GetValue() > 330) continue;
        }
    }

    int value = target.VisibleType.GetValue();
    if (pKing > bestProb + 1e-4f ||
        (Math.Abs(pKing - bestProb) <= 1e-4f && value > bestValue))

        best = moves[i];
        bestProb = pKing;
        bestValue = value;
    }

```

三道保险（v61 加入第 2 条）：

1. `P_King < 0.9` 时，走完后真王会被敌方“可能本态”反吃 → 放弃该步；
2. `P_King < 0.9` 时，走完后己方真后/真车暴露在敌方“可能本态”攻击下 → 放弃该步；
3. `P_King < 0.8` 时，只允许用价值 ≤ 330 的便宜子去试探。

被拒绝后不会直接放弃吃王，而是进入常规迭代加深——搜索仍可能选择这步，只是必须先算清代价。

## 8. Predator 外层（PredatorAI）

核心搜索仍然是 Hybrid/Expectiminimax；Predator 只在**根节点**加减分。它解决的问题是：

> 我们的搜索只按“我方真型 + 敌方信念”算分，但玩家知道自己的子是什么，也会按“AI 这枚子可能是王”来行动。Predator 用第二套 `BeliefState` 模拟“人类怎么看我们”。

### 8.1 镜像信念

`_mirror` 是一个以人类视角运行的 `BeliefState`，追踪**我方**棋子的本态：

```csharp
var humanView = _mirror.Clone();
humanView.NotifyMove(move, mover.VisibleType, LeakFor(board, move, mover),
    board, HumanSeesBait(board, move));
if (move.PromotionType.HasValue)
    humanView.NotifyPromotion(move.To);
```

`LeakFor` 判断这一步对玩家是“伪装走法”还是“可疑走法”：

```csharp
private static MoveLeakType LeakFor(Board board, Move move, Piece mover)
{
    return move.IsCastling || MoveGenerator.IsValidMoveForPieceType(
            board, move.From, move.To, mover.VisibleType, mover.Color)
        ? MoveLeakType.Disguised
        : MoveLeakType.Suspicious;
}
```

人类吃我方子时，镜像也要 `NotifyCapture`：

```csharp

```

这样 Predator 与玩家看到的公开信息完全一致，不读任何真实本态。

### 8.2 根评分公式

```csharp
if (mover.TrueType == PieceType.King)
{
    float kp = humanView.GetProbability(move.To, PieceType.King);
    float kpBefore = _mirror.GetProbability(move.From, PieceType.King);
    conceal -= kp * KingMoveAbsolutePenalty;
    conceal -= Math.Max(0.0, kp - kpBefore) * KingMoveDeltaPenalty;
    conceal -= KingMoveTempoPenalty;

    if (kingLossNow < 0.05)
        conceal -= KingRevealFixedPenalty;
    if (_reviewer.IsKingBaitCapture(board, move))
        conceal -= 3000.0;
}
if (move.IsCastling && ownKingBefore < 0.55f)
    conceal -= CastlingRevealPenalty;

// 2) 人类视角下，这回合真王被便宜子吃的概率
double risk = EstimateHumanKingLoss(after, humanView, enemyColor);
double destiny = EstimateGreedyKingCapture(after, humanView, enemyColor);
double magnet = EstimateHeavyPieceKingMagnet(after, humanView, enemyColor);

double total = conceal - risk * OwnKingLossWeight;
if (total > MaxTotalBonus) total = MaxTotalBonus;
else if (total < -MaxTotalBonus) total = -MaxTotalBonus;
total -= destiny;
total -= magnet * KingMagnetWeight;
```

### 8.3 三个风险估计

**人类视角吃王风险**（`EstimateHumanKingLoss`，`:325`）：

```csharp
var kingPos = after.FindKing(_color);
float pAtKing = humanView.GetProbability(kingPos.Value, PieceType.King);
if (pAtKing < 0.02f) return 0.0;

double survive = 1.0;
foreach (var (epos, _) in after.GetPiecesOfColor(enemyColor))
{
    float pAttack = BeliefAttackProbability(after, epos, kingPos.Value, enemyColor);
    if (pAttack > 0.0)
        survive *= 1.0 - Math.Min(0.95, pAttack);
}

return pAtKing * (1.0 - survive);
```

即：

$$
P(\text{真王被吃}) = P_{\text{king}} \times \left(1 - \prod_{\text{敌子}}(1 - p_{\text{attack}})\right)
$$

**必吃惩罚**（`EstimateGreedyKingCapture`，`:347`）：玩家是单层贪心，只要镜像里“这枚子可能是王”有一点苗头、且能落到那个格子，就可能不计代价扑王：

```csharp
bool canStrike = false;
foreach (var (epos, _) in after.GetPiecesOfColor(enemyColor))
    if (epos != kingPos.Value && AnyPossibleAttack(after, epos, kingPos.Value, enemyColor))
    { canStrike = true; break; }
if (!canStrike) return 0.0;

double urge = Math.Min(1.0, 0.4 + pAtKing * 6.0);
return urge * GreedyKingCapturePenalty;
```

**王磁铁**（`EstimateHeavyPieceKingMagnet`，`:376`）：镜像里某个大子的 `P_King` 高，玩家会用任意子来吃；如果它的真身是后/车，等于白送重子：

```csharp
if (piece.TrueType == PieceType.King) continue;
int value = piece.TrueType.GetValue();
if (value < 300) continue;

float pKing = humanView.GetProbability(pos, PieceType.King);
if (pKing < KingMagnetThreshold) continue;

bool reachable = false;
foreach (var (epos, _) in after.GetPiecesOfColor(enemyColor))
    if (AnyPossibleAttack(after, epos, pos, enemyColor)) { reachable = true; break; }
if (!reachable) continue;

penalty += pKing * value;
```

`AnyPossibleAttack` 只读安全掩码：

```csharp
int mask = _beliefState.GetSafetyMask(from);
if (mask == 0) mask = 0x7E;
for (int t = 1; t < 7; t++)
{
    if ((mask & (1 << t)) == 0) continue;
    if (MoveGenerator.CanPieceAttackSquare(board, from, (PieceType)t, attacker, target))
        return true;
}
```

### 8.4 与主引擎的接线

```csharp
protected override void PrepareReviewer(Board board)
{
    if (!_mirrorReady)
    {
        _mirror.ResetFromBoard(board, knownTruth: false);
        _mirrorReady = true;
    }

    ComputeRootBonuses(board);
    _reviewer.RootMoveBonus = _bonusLookup;
    _reviewer.KingRescueRisk = LookupKingRisk;
}
```

- `RootMoveBonus`：只参与根节点选子，不进入搜索树；
- `KingRescueRisk`：给王红线的重子救援豁免提供“玩家视角吃王风险”。

设计原则：外层只做“人类视角修正”，不重复搜索内部已经算过的材料/战术；历史上删掉过重复项，胜率反而上升。

## 9. 性能工程

### 9.1 探针

`PerfProbe.cs` 全部包在 `#if PERF_PROBE` 里，正式构建零开销。编译时加 `-define:PERF_PROBE`，对局结束打印：

```text
Evaluate           341141 ms  calls=72646573
  KingDanger         73803 ms
  ScanZones          93307 ms
  KingShield         13795 ms
  KingExits           4236 ms
  TrapRisk           16858 ms
OrderMoves           54333 ms
Generate             30166 ms
NegamaxCalls=... QNodeCalls=...
```

读法：`Evaluate` 的总时长减去各子项，就是材料/PST 主循环与其它项的成本。

### 9.2 v58 → v60 实测（同一台机器、同一 6 局诊断）

| 指标 | v58 | v60 |
|---|---|---|
| `Evaluate` 单次 | ~6.6 µs | ~4.7 µs |
| `KingExits` 总耗时（6 局） | ~54 s | ~4.2 s |
| `ScanZones` 单次 | ~1.74 µs | ~1.28 µs |
| 单次 `CountKingExits` | ~3.8 µs | ~0.2 µs |

结论：叶子评估是主战场；先做“等价但更便宜”的扫描，再考虑改算法。

### 9.3 优化原则

1. **先测量**：没有探针数据不改热点。
2. **先等价优化**：同样的评估分数、更少的扫描，不改变棋力语义，风险最低。
3. **差分测试**：临时宏（如 `ATTACK_VERIFY`）让新旧实现同时跑，比较每一处结果；确认 0 不一致后删除宏。
4. 不要凭直觉改剪枝深度：暗棋的战术威胁常落在视野外一层，减层很容易掉胜率（8 世界实验、Quiescence 深度实验都失败过）。

### 9.4 并行

- 常规多世界：`AdvanceParallel` 用 `Parallel.For` 一次跑一批世界，每个世界独占 TT/缓冲；
- 残局单世界：`AdvanceEndgameParallel` 按**根走法**切分，每个线程克隆棋盘、独占 TT/缓冲；
- WebGL（非 Editor）强制串行，避免线程支持问题。

分帧：Unity 里每次 `Advance(sliceMs)` 只占约 20ms 主线程，搜索跨帧推进。

- 单局结果不能用来证明改进；任何改动都要跑同协议 50 局，且最好跑两批。
- 240 步上限：双方都只剩王时必然判和，这是结构性平局，不代表引擎弱。

**v54 —— 王救援诱饵修正 + 重子挂子硬过滤**：这是第一个打到 98% 的版本。核心是“存在不挂后/车的走法时，不允许主动把重子送进 ≥25% 的火力”。

**v61 —— 绝杀通道加安全阀**：`FindImmediateKingCapture` 在 P_King 未达 0.9 时要求“吃王手不会送掉自己的真王/重子”，P_King < 0.8 时禁止低价值子（≤330）去赌。

**v62 —— 零节点塌缩修复**：王红线与重子挂子过滤同时排除掉全部根走法时，清空 `_hangingHeavy`，保证搜索始终有合法根集合。

**v63 —— 重子救援豁免 + 尾部风险厌恶**：

1. 确定性找出被 `BeliefAttackProbability ≥ 50%` 攻击的真后/真车；其逃子手若落点后续被攻击概率 < 25%，且王危险度不比当前差、镜像吃王风险 ≤ 10%，就允许绕过红线。
2. 根选择时若某走法的最坏采样世界比平均值低超过 450 分，超出部分按 0.4 权重收“保险费”。

**v64 —— 真后挂子阈值降到 10%**：修复 G0（75 步胜），但 G6 从平局变失败——原因是所有走法都挂后，`anyClean = false`，过滤被整体清空。

**v65 —— 真后强制救援**：当 `queenNow ≥ 10%` 时，比较走前/走后的真后危险度，只保留“能逃到 10% 以下”或“至少降低 15 个百分点”的走法。G6 由此从失败变 79 步胜。

**v65 的 50 局复跑（45 胜 / 3 负 / 2 平）暴露了真后救援的副作用**：三场失败全部是真王被吃。

- G18（36 步）：真后被 100% 咬住，`强制救援` 把根集合压到 3 手真后走法；王留在 e8 车线上，被下一步 `e8->e1` 直接吃。
- G32（26 步）：王走到 g5，正好落在 d8 真后的斜线上；该子在信念里“可能是后”，但概率低于 0.12，第二层按期望值放行。
- G35（229 步）：76 步真后吃象后被对方真后反吃，材料清零，K vs K+Q 拖到 229 步输。

前两局的共同根因：安全掩码（`GetSafetyMask`）已经把该子标成“可能滑子”，但概率阈值让低概率滑子通过。v66 因此把第一层从“干净手必须 ≤0.12”改成“只要有干净手，脏手一律排除”。日志见 `Tools/bench/v65_50_verbose.log`。

**v66 —— 王红线零容忍（最小改动）**：只要存在“任何可能本态都够不到真王”的走法，就把所有“掩码上仍可能被攻击”的走法直接排除，不再用 0.12 概率阈值给低概率滑子开口子；干净手之间不再按危险度二次筛选。两批同协议 50 局分别为 88% 与 90%，与 v65 持平，没有把胜率推高。

失败局仍是清一色真王被吃。最典型的是 #35：两批都在 25 步结束，真后伪装成兵从 d2 沿空 d 线吃掉 d7 的真王。终局面板显示 2650 对 22020，但这只是因为王本身按 20000 计入子力——吃王前双方约 22650 对 22020，基本均势，输的是一手猎王而不是子力崩盘。

复盘代码路径可以看到 v66 仍留了一个洞：`_threatResolvers`（拆火力手，落点正好是当前威胁源）只要概率危险度 ≤ 0.12 就会被加入 `exemptMoves`，而第一层的 `anyThreatFree` 会跳过所有 exempt 手。于是“吃掉一个威胁源、但掩码上还留着另一个威胁源”的手仍被当成安全手放行。G35 的 d8->f6 正是如此：它吃掉了 f6 的马，却把 d7 的王留在 d2 隐藏后的直线上；d2 是后/车的概率很低，所以危险度低于阈值。这说明“零容忍”必须作用在**掩码威胁数**上，而不是只作用在概率危险度上；拆火力豁免也需要复核走完后的掩码威胁数。

曾经试过更激进的版本——连干净手也按 0.12 危险度二次筛选——开局即出现“排除 19/20 手”，同一协议 50 局只有 39 胜（78.0%），已回退；这也是“红线越严越好”不成立的反例。

**v66 的进一步单局复盘（`KINGSAFETY_DBG=1`，`only=35`）**：致命回合 `anyThreatFree=False`，当前危险度 1.12、掩码威胁源 2 个；37 手里有 35 手被红线排除，只剩两手——`d7->d8`（王走，危险度 0.05）和 `f8->f6`（拆火力豁免，危险度 0.12，吃掉 f6 的马但王仍留在 d 线上）。也就是说，**这一回合本来就不存在“干净手”**，问题不是红线漏了某条规则，而是五步前已经把王走进了这个叉。最终引擎按自己的概率模型选了“最安全”的 0.05，对手恰好兑现了那个 5% 的后/车身份。

这也解释了为什么 v67–v69 继续收紧红线无法提升胜率：它们只能改变“没有干净手时选哪一手”，而这类回合在一局里只有 1–2 次（G35 为 1 次、G12 为 2 次，其余回合 `anyThreatFree=True`），其余 95% 的决策不受影响，却可能被新规则误伤。

公平性方面也做了反向核查：HumanModel 的 `EvaluateCapture/EvaluateProbe/KingAttackProbability` 只用 `_beliefState.GetProbability` 和公开的 `HasMoved`，`TrueType` 只读取它自己的走子；它并没有偷看我方真王。它之所以频繁吃王，是因为 `pKing × KingJackpot` 的期望让低成本试探在 50 局里反复兑现。

**采样数翻倍的 A/B（不采纳）**：曾假设高杠杆方向是提高稀有本态在采样世界里的覆盖率（16 个世界对 5% 的本态平均只覆盖 0.8 次），于是把采样世界从 16 提到 32，跑了两批同协议 50 局：第一批 45 胜 4 负 1 平（90.0%），第二批 41 胜 7 负 2 平（82.0%），合并 86.0%。同日 16 世界对照是 84.0%，v66 历史两批是 88%/90%。两批之间 8pp 的落差本身就说明单批不能作结论，而 32 世界没有带来可复现的提升，反而在第二批把平均节点数从约 67 万拉到约 127 万/步、总耗时从约 600 秒拉到 724 秒。更关键的是败局形态：这些失败局的致命回合里，王危险度已经到 0.48 这类量级，日志直接写“没有完全安全的手”，继续增加采样世界改变不了候选集。真正的缺口是**更早地不让王进入这种没有干净解的区域**。因此生产默认采样数维持 16，后续方向转向搜索深度/节点吞吐与中局王区预判，而不是继续加采样或加红线。

**v70 冒烟尝试（已回退）**：先按这个思路做了“给最可能攻击我方真王的敌子放大危险本态权重，并把它放在前两个世界”的重要性采样。单局 G35 复盘暴露两个问题：热点选择按最大概率会选中已被走法几何锁定的马（p≈1.00），真正致命的低概率滑子根本选不到；更关键的是王红线按信念概率筛手，一个偏置世界即使看见了隐藏后，也改变不了幸存的候选集。该改动只做了 G35 单局冒烟、没有进入 50 局验证，已整体回退。

**v72c —— 叶节点掩码暴露（逐格扫描口径）**：`MaskKingExposure` 对每个掩码敌子按“直线方向 Q|R、斜线方向 Q|B”做射线扫描，统计“可能本态”攻击真王的概率，再叠加潜在滑子惩罚；不是先选一个最危险子再展开。这个口径在 20,000 个随机局面上与 `bench_v72c.dll` 逐值比对 20,000/20,000 完全一致，因此作为后续版本的暴露基准。同协议 50 局 48 胜（96.0%）。

**v73 / v74 / v76 —— 三次低于基线的实验（已回退）**：v73 采用另一种暴露近似（90.0%）；v74 改为“射线 + 威胁世界”（92.0%）；v76 尝试“清洁救援”式过滤（88.0%，还多出两场 240 步平局）。三版都低于 v72c 的 96%，说明对叶评估/救援做额外近似没有稳定收益，最终回退到 v77 的逐格扫描口径（48 胜，96.0%，失败局仍是 #1 与 #18 的真王被吃）。

**v78 —— 真后救援的期望损失闸门（负面实验，已回退）**：思路是当真后危险度低于真车时，不再用“只救后”的硬过滤砍掉保车手。靶向回放 G18 确实按预期生效（第 3 手从 `b1->c3` 变成 `g1->h3`），#18 也从负变胜（128 步对手三次重复判负）；但整批只有 46 胜 / 3 负 / 1 平（92.0%），低于 v77 的 96.0%，新增 #7（145 步）与 #35（25 步）两负。需要说明的是，这两局里闸门一次都没有触发，92% 与 96% 的差距混有 12 局并发的时序噪声；但 G18 的“胜”只是对手三次重复判负，AI 子力照样被打到只剩真王，没有证据表明这是强度提升，因此按“单批负面即回退”的既定标准回到 v77 语义。

**v79–v83 —— 威胁世界与批次方差**：v79 用 v77 语义复跑（12 并发）只有 44 胜（88.0%），与 v77 单批 96% 相差 8 pp，说明 96% 本身不是稳定值；失败集合（#1/#7/#10/#18/#35/#43）仍是同一批“真王被吃”的局。随后尝试把“威胁采样世界”用于期望评估：v80 90.0%，v81 把威胁世界直接计入平均值只有 82.0%（4 场 240 步平局，威胁世界把平均分拖向保守），v82 改为只做尾部否决回到 90.0%。结论：**威胁世界可以作为否决项，不能作为均值项**。v83 只做了冒烟，未进入 50 局表。

**v84–v85 —— 赌博豁免与索引修正**：v84 给“挪王”增加赌博豁免，90.0%；v85 修正威胁世界索引（`threatWorld = start + i == _threatWorldIndex`）后 92.0%（46 胜 / 4 负）。同一时期把基准并发从 12 降到 6，量测更稳定。失败局仍是 #7/#18/#35/#43，全部真王被吃，且多数在 10–20 手时胜率预估已跌到 5%–35%，说明败因是中局前段的子力崩盘，而不是残局收束。

**v86 —— 重子“对手视角猎王”近确定定价（当前基线）**：v85 的 G18 日志给出直接证据：我方真后停在 e2（可见标签“兵”），人类镜像信念给该格的 P_King 已达 73%，下一步人类用真车直接吃走。旧定价 `pKing × value` 只收 0.73 × 900 ≈ 657，而人类实际收益接近整子；v86 在 P_King ≥ 0.19（HumanModel 绝杀通道的固定门槛之上）时按“整子几乎必丢”定价，并给有保护的格保留最小 100 分交换价值。固定协议两批结果：第一批 47 胜 / 3 负 / 0 平（94.0%），第二批 45 胜 / 3 负 / 2 平（90.0%），合并 92 胜 / 6 负 / 2 平（92.0%）。两批失败局**完全相同**（#0、#24、#35），说明这三局是稳定漏洞而不是并发噪声；#3/#18 是双方只剩王的 240 步结构性平局。失败局 #0 与 #24 都是真车/真后落到“可能是车/后”的敌方静止子火力里，G35 则是开局王位过早暴露。

**v87 —— 静止未知子的重子火力（负面实验，已回退）**：用 `EXPOSURE_DBG=1` 复现 #0/#24 的致命手，发现真正吃车的敌车在信念里的 P(Rook) 只有约 11%–18%（随局面中未锁定候选数变化），永远够不到 `RookHangingThreshold=0.25`；而且 a8/h8 两枚杀手车全程未动，掩码没有收窄。于是尝试“对从未动过的敌子，把可能的 R/Q 攻击按至少 30% 计入挂子判定”。靶向复现非常有效：G0 与 G24 都从负转胜（123 / 119 步，子力 21100 / 21600）；但完整 50 局只有 42 胜 / 5 负 / 3 平（84.0%），平均步数从 79.1 涨到 106.7，总耗时从 909 s 涨到 1413 s；v86 中三场普通胜利（#2/#15/#17）全部被拖成 240 步平局，另新增 #7/#42/#49 三负。这条规则让引擎在开局/中局过度回避重子走法，赢棋拖成和棋。已整体回退，生产代码保持 v86 语义。

**v88 —— 移动重子“无保护 + 敌重子火力”硬过滤（负面实验，已回退）**：v86 的三场稳定失败局里，我方真后/真车都是**自己走到**一条由未锁定敌子控制的直线后被杀（G35：真后 d8->e7，下一步被 e2 真后沿 e 线吃；G0：真车 d1->h1，下一步 h8 真车吃）。单个未锁定敌子的 P(后/车) 只有 7%–11%，低于 `QueenHangingThreshold=0.10` / `RookHangingThreshold=0.25` 的并集判定。v88 只对“本步移动的重子、且该格无保护”单独统计“敌方本态为后或车”的并集概率，≥10% 即判挂子；静止重子完全不计，以避免 v87 的全盘收紧。50 局结果 42 胜 / 6 负 / 2 平（84.0%），比 v86 的 92% 低 8 个百分点，失败局从 #0/#24/#35 扩散到 #5/#18/#21/#24/#32/#43。根因仍是同一个：暗棋里未锁定敌子的重子概率几乎处处 ≥10%，这条规则等价于“禁止无保护重子走直线”，把大量必要的进攻/兑换手一并禁掉。已整体回退，生产代码恢复 v86 语义。

**当前结论**：固定协程协议下 v77 的 96% 无法复现（v79 同语义 88%），v80–v88 的稳定区间是 90%–94%，当前基线 v86 = 92%（两批 94%/90%）。失败局几乎全部是 `KingCaptured`，且大多在中局前段就已失去胜率；下一步不应继续叠加“更严的硬红线”（v67–v69、v87、v88 都是反例），而应从搜索效率/评估校准与开局王位选择入手。

**真实对局棋谱记录器**：`Assets/Scripts/Simulator` 侧新增了逐手记录器，只记录公开信息（走法、可见标签、泄漏类型），不写任何本态；已随代码编译通过，但本会话没有在 Unity 实机对局中触发验证，报告中按“已实现、未实机演练”标注。

## 13. 常见问题（答辩预备）

**Q：这不就是极小极大吗？**

A：核心是负极大值 αβ，但暗棋有隐藏信息，所以外面套了“采样期望”：对 16 个可能的对手本态世界分别搜索，再对根走法取平均。这不是完全信息博弈，严格说是“信念空间上的期望搜索”。搜索树内部在每个采样世界里仍是确定的完全信息博弈，因此可以完整使用 αβ 剪枝。

**Q：AI 怎么知道对手的王在哪？**

A：不知道。它只知道每个敌子位置是王的概率，概率来自“剩余数量先验 + 走法几何 + 吃子条件化”。只有概率足够高（默认 0.8）时才允许把“吃采样王”当成真绝杀。

**Q：为什么吃子不告诉 AI 吃的是什么？**

A：为了公平。规则层只公开“少了一个子”，双方获得同样的信息；AI 若被允许读取 `TrueType`，就相当于开透视。项目里所有公平性检查都以此为准。

**Q：为什么不用神经网络？**

A：当前评估函数 + 采样搜索在 50 局基准上已接近上限，且完全可解释、可调试、CPU 可跑；神经网需要大量训练数据与算力，收益不确定。作业要求也是展示对搜索算法的理解，而不是堆模型。

**Q：最大的技术难点是什么？**

A：暗棋里“王的位置”是概率变量，任何一步都可能因为对手真王突然现身而翻转胜负；因此必须在搜索外再加王安全硬约束，并保证所有推断只用公开信息。另一个难点是“概率的尾部”：3% 的偷王在单局里就是 100%，所以还需要尾部风险与强制救援这类非期望准则。

**Q：为什么根节点要有硬过滤，不能全交给搜索？**

A：因为搜索的分数是 16 个世界的平均，而真实对局只发生在一个世界里。丢真王/真后这种“单世界灾难”在平均值里会被摊薄；硬过滤相当于把“不可接受的世界”直接删掉，再用搜索在可接受集合里比较。

**Q：Predator 和主引擎是什么关系？**

A：主引擎负责“在当前信息下最强的走法”；Predator 是外层修正，模拟“人类怎么看我们”，防止 AI 因为伪装被识破而丢王。Predator 不改搜索树，只改根节点评分，因此可解释、可单独关闭做 A/B。

**Q：如果玩家也写一个同样的 AI，谁会赢？**

A：信息完全对称，双方都用同一套信念更新与搜索，胜负取决于搜索深度、时间预算和根节点约束的细微差别。项目的公平性测试就是为了保证没有一方能读到对方真型；在这个前提下，暗棋更接近“带隐藏信息的博弈”，先手和随机布局会显著影响结果。
