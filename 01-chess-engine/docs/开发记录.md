## 1. 用户目标与铁律（不可违反）

### 1.1 目标
- 对 HumanModel（拟人本手模型）胜率 **至少 98%**，用户的原话是"必须要100%胜率，至少98%"。
- 完整开发权已下放：可以换架构、换算法，甚至神经网络（但这台电脑性能有限，重方案不可行）。
- 用户只做最后验收，不中途过问。

### 1.2 公平性铁律（用户明确报过 bug）
- AI 决策**绝不读取对手 `TrueType`**。只能用：公开标签 `VisibleType`、走法几何、吃子/数量约束、`BeliefState` 概率、`PossibleMask`、公平检查棋盘上的 `BeliefTypeMask`。
- **双方吃子都不应获知被吃子的真型**：已修复，`NotifyCapture` 只按"非王"条件化，不揭示。
- 升变类型（=Q/R/B/N）是公开信息，可以精确入信念（v92）。
- 不允许"透视"：判断敌方攻击必须走"可能本态"（掩码 + 概率），不得用敌方真实棋子类型。

### 1.3 工程约定
- 每次 AI 改动都要按**固定协议跑 50 局**并给报表；**单批负向即回退**。
- 同一时间只允许一个"写日志的 benchmark"进程（会互相抢 CPU，wall-clock 搜索下结果不可比）。
- 测试期间不要跑其它吃 CPU 的任务（编译、Unity、探针都会扰动 wall-clock 搜索）。
- 不得用 Play+paused 模式（Unity MCP 会死锁）。
- 敏感脚本/配置写入需要用户在聊天里文字授权；普通源码编辑已授权。
- 交付前必须：Unity Console 无报错 + 场景层级验证 + 清理临时诊断文件。
- 不主动 commit / tag / push，除非用户确认。

### 2.1 PieceType 位值（容易搞错，已踩过坑）
`King=1→bit0x02, Queen=2→0x04, Rook=3→0x08, Bishop=4→0x10, Knight=5→0x20, Pawn=6→0x40`，`AllTypesMask=0x7E`。
所以 `0x06 = 王|后`，`0x4E = 王|后|车|兵`，`0x16 = 王|后|象`。不要按"后=0x02"误读。

## 3. 构建与评测（照抄即可）

### 3.1 无头编译（Windows，Unity 自带 SDK）
```bash
DOTNET="D:/Unity/2022.3.62f3c1/Editor/Data/NetCoreRuntime/dotnet.exe"
CSC="D:/Unity/2022.3.62f3c1/Editor/Data/DotNetSdkRoslyn/csc.dll"

REFS=$(ls "$REF"/System*.dll | grep -v Native | sed "s|^|-r:|")
"$DOTNET" "$CSC" -nologo -target:exe -langversion:latest -noconfig -nostdlib+ -nowarn:0649 \
  -out:Tools/bench/bench_<版本>.dll $REFS \
  -r:"$REF/mscorlib.dll" -r:"$REF/netstandard.dll" -r:"$REF/Microsoft.CSharp.dll" \
  Assets/Scripts/Core/*.cs Assets/Scripts/Logic/*.cs Assets/Scripts/AI/*.cs Assets/Scripts/Simulator/*.cs
cp Tools/bench/bench_v92.runtimeconfig.json Tools/bench/bench_<版本>.runtimeconfig.json
```
- 必须用**完整 dotnet 路径**，PATH 里没有 dotnet。
- BUILD_EXIT=0 且无 error 才算编译通过。

### 3.2 固定 50 局协议（官方口径，不许改参数）
```bash
cd D:/myprogram/Chess
"$DOTNET" Tools/bench/bench_<版本>.dll battle predator 50 3000 6 400 1400 64 16 6 \
  noponder shuffled aiformation style=Aggressive outcomes verbose \
  > Tools/bench/v<版本>_50_c6.log 2>&1
```
参数含义：50 局 / 总预算 3000ms / 并发 6 / HumanModel 400ms / Predator 1400ms、16 采样、目标深度 6 / 64 置换表 / no ponder / 随机洗牌开局 / 阵型 A / 激进风格 / 输出逐局结果 / verbose。
- 偶数局 Predator 执白，奇数局执黑。
- 约 16 分钟跑完。

### 3.3 重要不确定性
- 搜索按 **wall-clock** 截断：并发数、机器负载、任何额外进程都会改变结果。**不同批次的局号会漂移**。
- 用 `concurrency 1` 重放某局**不可信**（会发散）。
- 诊断开关（`KINGSAFETY_DBG` 等）会拖慢搜索，诊断跑的胜负不能直接和官方批次比较。
- 已知 bug：`only=<n>` 且 `games` 不大于该局号时 `RunBatch` 会 IndexOutOfRange。
- 控制台中文可能乱码，把 trace 写进 UTF-8 文件再用 Read 看。

### 4.3 v95（已回退）：王亲自赌王的反吃兜底 → 88/100
批 1：45胜3负2平；批 2：43胜5负2平。合计 88/100，低于 v92 的 91/100，按约定回退两处行为改动（快通道 paranoid 用法、赌王豁免条件），源码恢复 v92 行为；`IsSquareAttackedByAnyPossibleEnemy` 等基础设施保留给 v96 使用。

### 4.4 v96（已保留）：王走子全类型避让 → 94/100
在 v92 基线上，对**真王自己的根走法**做超保守检查：走完后王所在格若被任意敌子按任意可能类型攻击（`IsSquareAttackedByAnyPossibleEnemy`），加入王红线；若会把全部根手封死，则撤回本次新增（既有红线保留）。
证据：G7/G19/G32/G43 的吃王手在发生前都不在掩码射程内——敌方用伪装标签允许的走法把掩码压在窄集合里（如伪装马的真车只走马步），直到最后一手才露真型吃王。概率红线对此无能为力，只能让王本身避让”任意可能射程”。

成绩：批 1 = 47胜2负1平（败 #18 76 步、#35 25 步；和 #24 240 步）；批 2 = 47胜2负1平（败 #18、#35，同一对局；和 #32 240 步）。两批均为 94%，超过 v92 的 91/100，按协议保留。
边界：只覆盖”王自己走”这一半。王原地不动、或王被迫留在射线上时仍无解（#35 即此：王全程在开放 d 线上，25 步被吃）。这也是 v97 的入口。

### 4.5 v97（已保留）：急险时“更安全的王走法”做统一上限
取证（复现 #35，`Tools/bench/v96_g35_ksdbg.log`）：第 24 手根节点，王在 d7、当前危险 1.12（2 威胁）；王走 `d7->e7` 危险仅 0.08，但王阈值是 0.06 → 进红线；后吃 `d8->f6` 马危险 0.12，被“拆火力手豁免”（≤ 0.12）放行。结果唯一根手是吃马，王留在开放 d 线，敌真后 `d2->d7` 吃王。
v97 改动（`ComputeKingSafety`，三处）：
1. 算完每手危险度后，若 `_kingDangerNow > KingSafetyUrgentDanger`，记录最安全的王走法 `bestKingEscapeDanger`；
2. 若 `bestKingEscapeDanger ≤ KingSafetySafeDanger`（0.12），非王拆火力手的豁免上限收紧到 `bestKingEscapeDanger + 0.001`（原来是 0.12）；
3. `anySafe` 分支里，所有手（含王走法）统一用 `bestKingEscapeDanger + 0.001` 作为上限。
只在“王已经在急险中、且存在半安全的王走法”时触发，王走法 0.08 能过线，危险 0.12 的静手被排除。
冒烟：`only=35` 单局复跑从 25 步败变为 50 步胜（`Tools/bench/v97_g35_smoke.log`）。
批 A 结果：48胜2负0平 = 96%（败 #18 76 步、#44 30 步；#44 是中局交换崩盘后的绝境，非典型王安全漏判）。批 B：49胜1负 = 98%（只负 #18），两批合计 **97/100，按协议保留**。#44 在 v96 与 v97 批 B 均胜，属 30 步时间噪声；#18 由 v98 处理。

### 4.6 v98（已回退）：赌王豁免要求“没有可信反吃” → 95/100
`KingCaptureGambleProb=0.25` 的赌王豁免原来无条件生效（v92 起）。v98 在豁免前执行该走法，若吃完后王格被敌方“可能本态”攻击的概率（`BeliefAttackProbability`，按掩码条件化求和）≥ `KingCaptureGambleCounterThreshold=0.50`，则拒绝豁免，交给红线。
证据：G18 第 75 手王 `e2->e3` 吃“35% 疑似王”，却被 82% 可信的敌车 b3 沿第 3 横排反吃，下一手丢王；该局在 v92/v96/v97 所有批次都是败局，v98 单局复跑变为 124 步胜（`Tools/bench/v98_g18_smoke.log`）。
注意与 v95 的区别：v95 曾把豁免收紧为“吃完后危险度 ≤0.12”，两批合计 88/100 已回退；v98 只拦“≥50% 概率可反吃”的强反制，阈值更宽。
批 A 结果：48胜1负1平 = 96%（`Tools/bench/v98_50_c6_a.log`）。G18 连续 5 批的 76 步必负 → 240 步和棋（核心收益确认）。唯一负局 G1（89 步，子力 420 vs 20400）：与 v96/v97 三批的 62 步速胜相比，分歧出现在第 4 手——v97 在第 2 层全样本回退选 `b8->c6`，v98 在第 3 层全样本回退选 `e7->e5`（两者都吃满 1401ms，节点数 142k vs 149k），是 wall-clock 深度噪声，不是 v98 代码路径（该逻辑只在“王吃疑似王”根手上执行，第 4 手不触发）。
批 B 结果：47胜1负2平 = 94%（`Tools/bench/v98_50_c6_b.log`；负 #44 30 步，和 #18/#49 均 240 步）。两批合计 **95/100，低于 v97 的 97/100，按协议回退**：删除 `KingCaptureGambleCounterThreshold` 与豁免循环里的 `fair.ExecuteMoveWithUndo`/`BeliefAttackProbability` 检查。G18 的和棋收益不足以抵消 #44 的确定性败局——回退后 v99 转向时间/深度问题，而不是继续加王安全约束。

### 4.7 v99 → v100（已全部回退）：2 层浅搜追加预算
根因（v97/v98 两批败局复盘）：1400ms 内完成 2 层还是 3 层，会直接改变根手选择，而这只取决于 wall-clock 抖动。
