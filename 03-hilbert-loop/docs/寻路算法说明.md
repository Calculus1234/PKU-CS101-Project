# 寻路算法说明（A*）

> 本文解释《大限将至》里 NPC 怎么从 A 房间走到 B 房间。
> 用的是开源库 **A* Pathfinding Project**（免费版），所以重点讲清**算法本身**
> 以及**本项目怎么接、怎么兜底**，而不是复述插件 API。

---

## 1. 为什么需要寻路

游戏是一层 ∞ 形走廊 + 9 个房间。NPC 有日程（起床 → 搜证 → 开会 → 投票），
必须在房间之间移动，而中间有墙、门、家具。

直接朝目标点走会撞墙。所以需要：

- 一张**可通行图**（哪里能走）
- 一个**最短路算法**（怎么走最近）
- 一套**降级策略**（图不可用/路径失败时别卡死）

---

## 2. 为什么选 A*

| 候选 | 优点 | 缺点 |
| :--- | :--- | :--- |
| **BFS / Dijkstra** | 一定找到最短路 | 盲搜，均匀扩散到所有方向，格点多时慢 |
| **A\*** | 最短路 + 方向引导，快得多 | 需要一个**可采纳**的启发式函数 |
| **NavMesh** | 连续空间、路径自然 | 需要烘焙、动态门/家具改动要重烘 |

**选 A\* 的理由**：网格化后状态数可控（一层楼几百个格子），A\* 在有方向的搜索下
扩展节点数通常只有 Dijkstra 的几分之一；而且改门/家具只需要改格子可行走标记，不用重烘。

---

## 3. 算法核心

### 3.1 评价函数

A\* 对每个候选格 x 计算：

```
f(x) = g(x) + h(x)
```

- **g(x)**：从起点走到 x 的**已付出代价**（实际步数 × 单格代价）
- **h(x)**：从 x 到终点的**估计代价**（启发式）
- **f(x)**：经过 x 的总代价估计

每次从「开放集」里取 **f 最小**的格子扩展。

**关键性质**：只要 `h` **不高估**真实距离（可采纳，admissible），A\* 找到的就是最短路。

### 3.2 启发式函数怎么选

| 移动方式 | 合适的 h | 说明 |
| :--- | :--- | :--- |
| 只能上下左右（4 邻域） | **曼哈顿距离** `|dx| + |dy|` | 与真实步数完全一致 |
| 允许斜走（8 邻域） | **Octile 距离** `max(dx,dy) + (√2−1)·min(dx,dy)` | 对角走 √2、直走 1，不会高估 |
| 任意方向 | **欧氏距离** `√(dx²+dy²)` | 最精确，但计算稍贵 |

> 本项目用 **Grid Graph + 8 方向**，对应 **Octile 距离**。
> 如果误用了欧氏距离而图是 8 方向、斜走按 √2 计，`h` 会**低估**——不会出错，只是搜索变慢（A\* 退化成接近 Dijkstra）；
> 反过来若用曼哈顿距离配 8 邻域，`h` 会**高估**对角距离，就可能找不到最短路。**这是最容易踩的坑。**

### 3.3 数据结构

- **开放集（open set）**：待扩展的格子，按 f 排序 —— 标准实现用**二叉堆（优先队列）**，取最小 O(log n)
- **关闭集（closed set）**：已扩展的格子，避免重复处理
- **cameFrom**：记录每个格子是从哪来的，用于最后回溯路径

---

## 4. 伪代码

```
A_STAR(start, goal):
    open ← 优先队列（按 f 排序）
    g[start] ← 0
    f[start] ← h(start, goal)
    open.push(start, f[start])

    while open 非空:
        cur ← open.pop_min()              # 取 f 最小的
        if cur == goal:
            return 回溯路径(cameFrom, cur)

        if cur in closed:  continue        # 旧副本，跳过
        closed.add(cur)

        for nb in neighbors(cur):          # 8 方向
            if 不可通行(nb):  continue

            stepCost ← 1.0（直走）或 1.414（斜走）
            tentativeG ← g[cur] + stepCost

            if tentativeG < g.get(nb, ∞):
                cameFrom[nb] ← cur
                g[nb] ← tentativeG
                f[nb] ← tentativeG + h(nb, goal)
                open.push(nb, f[nb])       # 允许同一格子多次入队（惰性删除）

    return 无路径
```

**两个工程细节：**

1. **惰性删除**：不实现「修改队列中已有元素的优先级」，而是直接 push 新副本，
   pop 出来时检查是否已在 closed 集合。实现简单，代价是最多多存一点节点。
2. **邻居顺序**：8 方向时先检查是否穿墙角——对角移动必须两个正交邻格都可走，
   否则角色会擦着墙角穿过去。

## 5. 在本项目中的实现

### 5.1 分层

```
行为树节点（MoveToTarget / MoveToSuspectRoom / ...）
        ↓ 调用
NPCNavigator（统一接口：MoveTo / Stop / IsArrived / ConsumeGiveUp）
        ↓ 优先
AStarBridge.RequestPath(from, to, callback)   ← 包一层插件
        ↓ 失败/不可用
直线兜底（球体扫掠防穿墙）
```

**为什么要包一层 `AStarBridge`**：把第三方库的 API 收敛到一个文件里。
将来换寻路库只改这一个类，行为树和 NPC 代码不受影响。

### 5.2 网格图

用插件的 **Grid Graph**，在编辑器里烘焙（免费版不支持运行时扫描）。
每格约 0.5 m，层的可行走性由碰撞体决定。

**动态障碍**（关着的门、临时家具）用 **GraphUpdateObject** 局部更新，
不用重烘整张图。

### 5.3 两级降级

`NPCNavigator` 的设计目标是**任何情况下都不能卡死**：

| 情况 | 行为 |
| :--- | :--- |
| A\* 可用、路径可达 | 沿 `ABPath.vectorPath` 移动 |
| A\* 路径失败（目标不可达） | 置 `GiveUp`，行为树换点重试 |
| 网格未烘焙 / 插件缺失 | **直线走 + 球体扫掠**：按身体半径（0.35 m）向前探测，遇到障碍就停 |

**直线兜底的扫掠**：用两个采样高度（身体上下各一处）做球体检测，
按全身宽度判定，所以**不会穿墙，也不会把身体插进床/桌子**。

### 5.4 自动开门

接近「关着且未上锁」的门时，NPC 会自主开门并等门开完再继续走：

```
探测距离 1.4 m
等门超时 1.2 s（超时不再等，继续走或放弃）
```

**这解决了一个真实问题**：A\* 认为「门格可通行」（门没锁），
但物理上关着的门挡路——不处理的话 NPC 会贴着门原地抖动。

### 5.5 卡死保护

```
每 0.5 s 检查一次位移：
  位移 < 5 cm → 记一次
连续 5 次（2.5 s）→ 放弃当前目标，置 GiveUp
```

行为树收到 `GiveUp` 后换下一个候选目标点。
**没有这层保护，一个被家具卡住的 NPC 会永远停在那里，整个日程停滞。**

---

## 6. 与行为树的集成

行为树的**移动类节点**统一走这套接口：

```csharp
navigator.MoveTo(targetPos);          // 发起移动
// 每帧：
if (navigator.IsArrived) → SUCCESS
if (navigator.ConsumeGiveUp()) → FAILURE（由 Selector 换下一个分支）
```

节点不需要知道底下是 A\* 还是直线——**这就是封装的收益**。

---

## 7. 复杂度

| 指标 | 值 |
| :--- | :--- |
| 时间 | 最坏 O(E log V)，E 为边数、V 为可行走格数；有可行启发式时实际远小于此 |
| 空间 | O(V)：g/f 表 + 关闭集 + cameFrom |
| 本场景规模 | 一层楼、格点约几百到几千，**单次寻路 < 1 ms** |

**性能瓶颈不在寻路上**——NPC 的思考（行为树 + 偶尔的 LLM 调用）才是。
所以这里优先保证**正确性与不卡死**，而不是极限性能。

---

## 8. 已知局限

1. **免费版不能运行时扫描**：网格必须在编辑器里烘焙，动态改动靠局部更新。
2. **8 方向网格**：路径是折线，需要简单的平滑（本项目用 `vectorPath` 的原始折点 + 转向阈值）。
3. **没有多 NPC 避让**：多个 NPC 同时走可能互相挤，靠物理碰撞体和卡死保护兜底。
