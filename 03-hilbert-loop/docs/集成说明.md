# 三方系统集成说明 —— A\* / Yarn Spinner / 行为树

> 本文档说明三个已安装插件与 HilbertLoop 的桥接方式。
> 三个桥接脚本都只提供"接口与通道"，不含任何游戏内容——内容由你在编辑器中配置/编写。

---

## 1. A\* Pathfinding Project —— 寻路网格一键生成

### 1.1 现状（已烘焙，无需手动配置）

主场景 `MainScene` 已包含烘焙好的 A\* 网格：**97 × 51 @ 0.5 m，4947 节点 / 1361 可行走**。
烘焙数据以 Base64 序列化在场景里（`Systems` 物体的 `AstarPath` 组件上），Play 启动直接反序列化加载，不做运行时扫描。
NPC 移动已由 `NPCNavigator` 接入 A\* 真寻路（Seeker + AIPath），行为树与节点零改动。

### 1.2 手动重新烘焙（场景改动后执行一次）

菜单：**`HilbertLoop → 生成寻路网格`**（编辑器模式，非 Play）。

**适用时机**：搬动墙体 / 家具、新增或改动地板、调整房间布局之后。

生成器自动完成：

1. 收集场景中全部 `Tag = Walkable` 地板，取整体外接盒（自动外扩 1 m）；
2. 创建（或复用）`AstarPath` 与 GridGraph，按 `Ground` / `Obstacle` 分层配置胶囊碰撞扫描；
3. 烘焙前临时打开"未锁且未破"的房门（让门洞在网格里连通；9 号房锁定门保持封闭）；
4. 烘焙结果**序列化进场景并保存**（Play 时免重扫）；Console 输出节点统计与 1~9 号房连通性自检。

> 自检预期：1~8 号房 → 圆桌区全部"连通 ✓"；9 号房（锁门）"不可达 ✓"。

### 1.3 调整网格粒度（改常量后重跑菜单）

改 `Assets/Editor/NPCGridGraphGenerator.cs` 顶部常量（均有注释）：

| 常量 | 默认 | 说明 |
| --- | --- | --- |
| `NodeSize` | 0.5 m | 节点大小；走廊宽 3 m / 门洞净宽 1 m，0.5 m 与之匹配；越小越精细、节点越多 |
| `CollisionDiameter` | 0.6 × NodeSize（实际半径 0.15 m） | 碰撞胶囊直径 |
| `CollisionHeight` / `CollisionOffset` | 1.6 m / 0.2 m | 胶囊圆柱高度 / 离地抬高（避开 2.2 m 门楣与地板自碰） |
| `BoundsPadding` | 1.0 m | 包围盒外扩（防止贴边地板首个节点落空） |

### 1.4 添加新的可行走区域

新地板（或替换成 FBX 后的新地面）设为 **Layer = `Ground`、Tag = `Walkable`**，然后重新执行一次菜单即可。
（程序化生成的场景由 `MainSceneBuilder` 自动完成分层 / 打标签；手工摆放的物体需自己设置。）

### 1.5 降级行为（网格缺失时）

场景中若没有烘焙数据（或 `AstarPath` 组件缺失），`NPCNavigator` 自动降级为**直线移动 + 球体扫掠防穿模** ——
不会穿墙 / 卡死原地，但不会绕路走门洞。两级逻辑对外接口一致（`MoveTo / Stop / IsArrived`），行为树无需感知。

### 1.6 代码接入（可选）

NPC 移动无需手动接线 —— `NPCNavigator.MoveTo` 内部自动选择 A\* / 直线。
如需在别的系统里独立请求路径 / 查询可走点，用 `AStarBridge`（桥接内部使用 `ABPath.Construct` + `AstarPath.StartPath`）：

```csharp
// 请求路径（回调在寻路完成时触发，通常同一帧末或下一帧）
AStarBridge.Instance.RequestPath(transform.position, target.position, (ok, path) =>
{
    if (!ok) { /* 兜底：直线移动或放弃 */ return; }
    // path 为世界坐标路径点列表，可按序移动
});

// 或取最近可通行点
if (AStarBridge.TryGetNearestWalkable(pos, 2f, out var walkable)) { /* ... */ }
```

## 2. Yarn Spinner —— 对话（内容全部留空，待编写）

### 2.1 场景接入

1. 从 Yarn Spinner 包中把 **Dialogue System 预制体**（含 `DialogueRunner` + 对话视图）拖入场景
   （或自己搭一个挂着 `DialogueRunner` 的节点）。
2. 创建 **Yarn Project**（右键 → Create → Yarn Spinner → Yarn Project），把 `.yarn` 脚本挂上，再指定给 `DialogueRunner`。
3. 把 `DialogueBridge` 组件放到 DialogueRunner 所在节点（或其父级）：它会自动查找 `DialogueRunner` 并转发事件。
   - 未接入时所有接口**安全降级**（只打警告），不会报错。

### 2.2 桥接 API

```csharp
var bridge = GetComponent<DialogueBridge>();
bridge.StartDialogue("room3_dagger");       // 运行名为 room3_dagger 的 Yarn 节点
bridge.StopDialogue();
bridge.SetVariable("$has_dagger", true);    // Yarn 变量（带 $ 前缀）
bool know = bridge.TryGetVariable("$knows_secret", out var v);
bridge.OnDialogueCompleted += () => { /* 对话结束后的流程 */ };
```

### 2.3 建议命名约定（供剧情编写参考）

| 触发时机 | 建议节点名 |
| --- | --- |
| 拾取纸条 | `note_<n>_read` |
| 打开 9 号房 | `room9_break_in` |
| 阶段变化 | `phase_meeting_start` / `phase_vote_start` |
| 轮回开始 | `loop_<n>_intro` |

游戏层不硬编码任何台词；文本请全部写在 `.yarn` 中。

## 3. MonoBehaviourTree（MBT）—— NPC 行为树（逻辑留空，待搭建）

### 3.1 场景接入

1. 在 NPC 节点（`NPCPlaceholder` 所在物体）下新建子物体，添加：
   - **MonoBehaviourTree** 组件（树容器）+ Root 子节点；
   - **MBTExecutor**（自动 Tick 开关）；
   - **Blackboard**（此 NPC 专属黑板）。
2. 把 `BehaviorTreeBridge` 挂到 NPC 根节点：自动查找上述三件套；找不到时接口安全降级。
3. 用 MBT 编辑器搭建行为逻辑（巡逻 / 追逐 / 交互 / 呼救…），"移动到目标"节点调用 **AStarBridge** 取路径。

### 3.2 桥接 API

```csharp
var bt = GetComponent<BehaviorTreeBridge>();
bt.Emit("npc_pushed", this);            // 广播玩法事件给行为树层
bt.SetTreeActive(false);                // 例如会议阶段冻结 NPC
bt.ManualTick();                        // 手动 Tick（关闭自动 Tick 时）
bt.GetVariable<BlackboardVariable>("target"); // 读黑板变量
float t = bt.PhaseTimeRemaining;        // 当前阶段剩余秒数（只读上下文）
```

### 3.3 建议事件表

| eventKey | payload | 触发点 |
| --- | --- | --- |
| `phase_changed` | `GamePhase` | `GameManager.OnPhaseChanged` |
| `npc_pushed` | NPC 自身 | `NPCPlaceholder.OnPushedOutWindow` |
| `npc_nudged`（模块三预留） | NPC 自身 | 暂无（非致命轻推：行为树事件接收器 —— 被推后强制转身、打断当前动作、触发怀疑度或对话；本轮未实现，待模块三接入） |
| `npc_killed` | NPC 自身 | `NPCPlaceholder.OnKilled` |
| `item_picked` | itemId | `ItemPickup.Interact` 成功后 |
| `door_broken` | 房间号 | `DoorController.OnDoorBroken` |

## 4. 游戏流程接线总览（推荐）

```
GameManager（阶段机）
   ├─ OnPhaseChanged ──► BehaviorTreeBridge.Emit("phase_changed") ──► 行为树切换 NPC 节奏
   ├─ OnPhaseTimeExpired ──► DialogueBridge.StartDialogue("phase_xxx") ──► 剧情对话
   └─ OnLoopAdvanced ──► 重置房间物品 / 尸体 / 门闩（自行实现场景复位逻辑）

InteractionSystem（E 交互；对准藏匿点时另有 数字键 1-9 / R 取回）
   ├─ DoorController / WindowController / ItemPickup / HidingSpot / NPCPlaceholder
   └─ 全部实现 IInteractable，新增可交互物只需实现该接口
```

### 物品效果（useEffectId）约定

`ItemDatabase.asset` 中已验证的字段示例（解析逻辑留给玩法层 / Yarn）：

| id | useEffectId | killChance | 备注 |
| --- | --- | --- | --- |
| dagger | `kill` | 1.0 | 必杀 |
| hammer | `kill` | 0.5 | 失败惊动全场；也可劈开 9 号房门闩（`DoorController.breakToolId = "hammer"`） |
| rope | `climb_window` | - | 预留 |
| magnet | `lock_window` | - | 9 号房窗磁铁 |
| nail | `climb_wall` | - | 预留 |
| cloak（面具斗篷） | - | - | canDiscard = false |
| note | - | - | 纸条，建议拾取后触发 Yarn 节点 |

> 注意：以上效果 id 均为**约定字符串**，具体的判定/动画/剧情请在 Yarn 或行为树中实现，核心脚本中没有任何写死的玩法分支。
